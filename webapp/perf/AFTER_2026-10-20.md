# Webapp performance and accessibility -- after, 2026-10-20

> **Measured on the pre-restructure shell** (merge base 4df3555a1, before the 3f3e3cad3 restructure and the
> section lanes). Kept for the record; a fresh AFTER measurement on the restructured export is still owed
> before perf/budget.json and perf/a11y-pages.json gate CI.

Same ten pages, same method and tooling as `BASELINE_2026-10-20.md` (Lighthouse 12.8 mobile and
desktop presets, best of two runs by TBT; axe-core 4.10 in both themes at 1280x900; static byte
accounting from the exported HTML), measured on the final build of the
`perf/webapp-baseline-2026-10-20` branch served locally with gzip. The deltas are against the
baseline tables; the full after-tables follow.

## Headline

- `/paper-trading/` is the page that moved: performance 74 -> 98 (mobile) and 87 -> 100
  (desktop), CLS 0.398 -> 0.001 and 0.247 -> 0.006, LCP 3.1 s -> 2.2 s mobile, accessibility
  97 -> 100 with zero axe violations in either theme (was 37 dark / 192 light contrast nodes plus
  two unreachable scroll regions).
- `/analytics/papers/` document 192 KB -> 34 KB gzip; mobile LCP 3.3 s -> 2.6 s, performance
  91 -> 97.
- Every analytics page ships 23-24 KB gzip less JavaScript (command palette on demand) and
  every terminal page 63 KB less image (nav logo 75 KB -> 12 KB), with TBT down on all of them.
- axe-core: zero serious or critical violations on all 20 page/theme combinations (baseline had
  four pages with serious findings). The one remaining finding of any impact is noted below.
- The skip link is still the first Tab stop everywhere and no tab stop in the first 25 lacks a
  visible focus ring, in either theme.

## Still open after this branch

- **LH `label-content-name-mismatch` (1 node, every terminal page, desktop preset)**: the nav
  logo link's `aria-label="CourtVision home"` does not contain its visible text
  "CourtVision multi-sport". `components/Nav.tsx` belongs to the navigation lane.
- **`/analytics/` mobile LCP 3.45 s (performance 91, unchanged)**: the `Workspace` client
  component receives every mechanism, entity and module as props (594 KB raw RSC flight data,
  91 KB gzip of HTML), and the hero emblem is preloaded at high priority next to the `<h1>` LCP.
  Both are decisions about what the workspace renders client-side -- analytics lane.
- **axe `page-has-heading-one` (moderate) on the paper trade detail**: the position line is now an
  `<h1>`, but only once the trail has resolved the row, and in the export every `/paper/<id>` page
  renders "trade not found: mlb%7Cmlb%7C..." (pre-existing; the baseline had no heading either).
  The route param arrives still percent-encoded once (the href is double-encoded so the host's
  single decode lands on the export directory), while `matchRow` in
  `app/(terminal)/paper/[betId]/BetDetailPageClient.tsx` decodes it only once before comparing
  with the trail rows. Decoding the param until it is stable, or comparing encoded forms, would
  make the demo detail pages render; that is the paper-desk lane's call.
- **`/paper-trading/` and `/paper/<id>` still download the recharts chunk** (it is now dynamic,
  after hydration, so it no longer blocks or shifts anything; Lighthouse's JS column counts every
  request in the trace, which is why those two pages show the same JS bytes before and after).
- **Dark `--danger-foreground`** (white) on `--danger` is 3.5:1 for filled badges; not on a
  measured page and a visible colour change, so left for the token owner.
- **Fraunces `opsz` axis (66 KB)**: dropping it saves ~25 KB but changes the display face's
  rendering; font-swap CLS is 0 on every analytics page, so left as is.
- `uses-long-cache-ttl`: GitHub Pages serves `max-age=600`; not controllable from the repo.
