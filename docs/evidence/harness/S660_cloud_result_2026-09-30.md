`kalshi_ws_capture.py` and `kalshi_ws_frames.py` are byte-identical to trunk e1b3bcdc (capture
sha256 ab3e45e71576acb94acf80f356d8720d2604b1dd0a23e13561e91ca655980b35, asserted by a test).

How it works: `python -m scripts.platformkit.ingame.kalshi_ws_signer <the same argv as
kalshi_ws_capture>`. The signer rebinds the capture module's `credentials` name. Each call (the
refusal check in main() and every connect in run()) signs fresh headers: RSA-PSS SHA-256,
MGF1 SHA-256, salt = digest length, over ts_ms + "GET" + "/trade-api/ws/v2". The headers go
atomically into a 0600 file at the path named by `--credentials-env-var`, and the unchanged
original reads them back. The file is removed when the run ends.

Environment variables (owner step 1): `KALSHI_API_KEY_ID`, `KALSHI_PRIVATE_KEY_PATH`, and the one
named by `--credentials-env-var` (recommended `KALSHI_WS_CREDENTIALS_PATH`). All three must point
outside the repo. The credential path must not already exist, and its directory must not be
group- or world-writable (POSIX).

## Fix round 1 (7283bdb68)

- The adversarial probe found a key-clobber path: if the credential env var named the private key
  file, the first write replaced the key and the finally block deleted it. main() now refuses
  (`credentials_path_exists`) any credential path that already exists, so it never overwrites or
  deletes a file it did not create.
- credential_path now stats the parent directory inside the try, and it refuses a parent that is
  not a directory.
- Tests C1-C4 were added.
