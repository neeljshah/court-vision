## 3. The bound (fill_realism_states.py, 61 lines; fill_realism_io.py 294 -> 296)

OmittedStates(db, fallback) is passed as state_counts. It reads every state receipt once per night
(`SELECT receipt FROM rows WHERE role='state' ORDER BY receipt`) and the market's selected receipts once per market
(market() is called right after every _load), each as int64 nanoseconds of the fixed-width format(at, '022.9f')
string. Per fill: after = all_after - selected_after and unmatched = (all - selected) - after, by bisect_right on
the same end string the old query compared. Why the counts cannot move: (1) fixed-width zero-padded digit strings
compare as TEXT exactly as their integers compare; (2) any receipt or end that is not the plain 22-character form
(sign, other width, non-ASCII digit, >= 2**63) routes every call to the old query; (3) zero counts are omitted as the
GROUP BY omitted them, same key order; (4) window <= 0 returns {} first and end is the same expression in the same
Decimal context, so exceptions surface in the same order. Memory: two int64 arrays (about 15 MB for 1.86 M receipts).

## 4. Why no per-market skip budget

The trace finds an algorithmic cause (an O(all state rows) scan per linked fill), so the bound keeps every market and
every byte. A skip budget would change the artifact whenever it fires and its cap would be chosen without a
measurement. If the PENDING replay still exceeds the deadline (e.g. the index phase on 1.86 M tennis state rows),
the skip-and-count budget (fill_realism_market_skipped, reason + market id) is the follow-up, sized from that profile.
