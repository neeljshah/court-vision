provably met takes the unchanged pre-S825 per-call path. Files (LOC): NEW scripts/platformkit/ingame/
baseline_four_arm_fit.py (120: fit_logistic / apply_logistic = the pre-S825 logistic body split with the

with the fold lists in walk_forward's order); baseline_four_arm_features.py (277: logistic delegates, so every

lagged_subset takes an optional view); baseline_four_arm.py (300: predict reads list / games / warmup / fits from
the view, the per-call purge and both asserts kept verbatim on the fallback path; two line joins elsewhere);
eval_gate/walkforward.py (175: keyword lazy_train, default False = unchanged for every other caller).

Why output-identical (spec section 1): predict's purged set is a function of boundary = midnight of first[gid]
only; select_rows refuses a tick after its close, so every purged-in state precedes boundary - 3 days <= test
tick - 3 days, and walk_forward's look-ahead, matchup-embargo and team-purge filters never drop one; the fold list
is built from the same stable string sort walk_forward uses, and the fold path is taken only when (i) that string
order agrees with fromisoformat order (checked once), (ii) the test tick is at or after its boundary, (iii) every
fold row precedes boundary - 3 days (checked once per fold). Record keys are written in the same order, so the
JSON bytes match.
