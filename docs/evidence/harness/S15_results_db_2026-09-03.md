## The metric -- re-proposal charges nothing (n = 2, CONSTRUCT)

Denominator: 2 proposals of the same hash at T2. Both are in the denominator;
the second is not excluded or renamed. Trace against a TMP ledger:

```
TWO-PROPOSAL TRACE (tmp ledger K before first = 0)
proposal 1: MISS -> charged trial, k_global=1, tmp ledger K=1, results=1
proposal 2: LOOKUP hit, k_at_run=1, tmp ledger K=1, results=1
```

BAR MET: 1 trial + 1 lookup; tmp ledger K = 1 before and 1 after the second
proposal (UNCHANGED); exactly 1 `result` row. The proposer contract is
lookup-first, charge-only-on-a-miss, and `results_db.py` contains no
`_charge_ledger` call at all -- indexing is not a trial.

## Red-team prerequisites (SF-12 / SF-13 / SF-14)

```
SF-13: lookup with a different corpus_sha -> None            (fresh trial, never a hit)
SF-14: stored deflated_p=0.34 at k_at_run=1; k_now=14
       -> verdict_needs_rescore=True, recompute_deflated_p(row, 14) = 1.0
SF-12: IntegrityError: UNIQUE constraint failed: hypothesis.hash
```

- **SF-13** `corpus_sha` is part of the UNIQUE key and of the `lookup()`
  signature, so a changed corpus misses and `record()` writes a second row.
  Confirmed in the test: 2 result rows for one hash across two corpus shas.
- **SF-14** `lookup()` always returns `k_at_run` (the stored `k_global`) and sets
  `verdict_needs_rescore` whenever the caller's `k_now` differs. The stored
  `deflated_p` is never presented as current; `recompute_deflated_p(row, k_now)`
  calls `scripts/platformkit/eval_gate/deflated_metrics.deflated_p` -- the one
  canonical deflation, not a reimplementation. Test case: stored
  `deflated_p(0.02, 3) = 0.06` at k_at_run=3 re-prices to `0.28` at k_now=14 and
  the row is flagged.
- **SF-12** two hypotheses that differ only in an unused param share a semantic
  hash (grid-snap). The second insert hits the `hash` primary key; the handler
  compares the seven stored RAW grammar columns against the incoming ones,
  re-raises `sqlite3.IntegrityError` when they differ, and is idempotent only
  when they are byte-identical. Collisions are surfaced, never merged.

## NOT VERIFIED

- **No concurrent claimer was actually run.** `claim()` uses `BEGIN IMMEDIATE`
  before its SELECT, which is the correct sqlite write-lock idiom, but atomicity
  is verified only SEQUENTIALLY (claim(2) then claim(2) in one process). A true
  two-process race is untested.
- **No crash/lease recovery.** A claimer that dies after `claimed_at` is stamped
  strands its rows forever -- there is no lease expiry or requeue. Flagged with a
  `ponytail:` comment in `claim()`. This is a known ceiling, not a measured one.
- **No multi-process WAL / locking test** against the production path; the DB was
  exercised single-process on tmp files only. The pod-authoritative single-writer
  assumption is inherited, not demonstrated here.
- **`grammar_version` is a caller-supplied string** defaulting to `"s11"`;
  grammar.py exposes no version constant, so nothing enforces that the stored
  value matches the grammar that produced the hash.
- **`corpus_sha` is caller-supplied.** This module does not compute it from the
  corpus_cache sidecar; the intended producer is
  `scripts/platformkit/autoloop/standing_prereg._gate_corpus_sha`. Wiring that
  producer to the foundry runner is NOT done in this lane.
- **No caller yet.** `results_db.py` has zero importers in master -- S12's
  `tiers.py` and the foundry runner still have to adopt it. The two-proposal
  saving is demonstrated on the module's own contract, not on live foundry
  traffic.
- **No real trial artifact was written** to `data/cache/eval_gate/trials/`; the
  directory does not exist and `trial_artifact_path()` was checked as a string
  only.
