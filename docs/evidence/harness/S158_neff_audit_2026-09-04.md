## Scope and premise (Q8 first)

The audited implementation is `scripts/platformkit/ingame/gap_effective_n.py`:

```text
deff = 1 + rho * (n_ticks / n_games - 1)
n_eff = n_ticks / deff
```

The S88 pooled premise was reproduced from the committed
`docs/evidence/harness/s88_phase_recal_2026-09-04.csv`, filtering its archived
informative rows and passing the archived loss differential through the helper:

```text
n_informative=11087  n_games=127  rho=0.7030964134497208
deff=61.676666861487725  n_eff=179.76003834479206
```

Those values reproduce the published pooled JSON to less than 1e-6. No real archived
row available here has `n_eff < n_games`.

For `n_ticks >= n_games` and `rho` in `[0, 1]`, `deff >= 1`, so `n_eff <= n_ticks`.
The supplied identity is:

```text
n_eff - n_games = (n_ticks - n_games) * (1 - rho) / deff >= 0.
```

Thus the formula guarantees `n_games <= n_eff <= n_ticks`; `n_eff` cannot support a
general upper bound of `n_eff <= n_games`. On non-singleton tick sets
(`n_ticks > n_games`), equality with `n_games` occurs exactly at `rho == 1`. The
identity also shows the necessary degenerate caveat: where `n_ticks == n_games`,
equality occurs for every rho. S87's published one-row-per-game reference is listed as
NOT VERIFIED below because its source CSV is absent. This is not an `n_eff < n_games`
counterexample and requires no formula change.

`n_eff_bound_ok` is additive and is computed from the same `rho`, `deff`, and `n_eff`:

```text
(n_eff <= n_ticks) and (rho < 1.0 or isclose(n_eff, n_games))
```

It is a diagnostic for the valid upper tick bound plus the rho-one/singleton equality
case; it neither changes `n_eff` nor changes any verdict.
