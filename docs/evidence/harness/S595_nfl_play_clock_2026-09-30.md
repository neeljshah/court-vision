## URL contract (spec BINDING BEFORE-CONDITION, measured 2026-09-29 before the build)

- `https://sports.core.api.espn.com/v2/sports/football/leagues/{league}/events/{event}/competitions/{event}/plays/{play}` (event id = competition id; play id = state.last_play_id verbatim).
- Measured: 200 responses of 1,792-4,939 B in 0.19-0.34 s; a missing id is 404, 52 B; `id` echoes the requested id as a string; `wallclock` is 'YYYY-MM-DDTHH:MM:SSZ'.
- The list endpoint (`.../plays?limit=1000`) is 749,188 B (nfl 401872963) / 872,157 B (ncaaf 401858461); one single-play GET is about 0.6 pct of that.
- Accepted rows: `state.last_play_ts` = wallclock verbatim, `last_play_ts_source` = `espn_core_play_wallclock`, `last_play_ts_reason` = null.
- Reason codes: no_play_id and no_event_id are written on the row and counted in module counters() only; every other null reason is counted as `play_clock_<reason>` on the per-source drop counter: http_404, http_403, http_429, http_error, timeout, connect_error, json_error, id_mismatch, wallclock_invalid, wallclock_future, tick_cap, tick_budget, play_hold (once per call), gave_up (once per pid), enrich_error.

## Emission

The keys ride `state`, so `_build_row` persists them unchanged (local_state_capture.py: 0 edits) and state_changed flips when ANY of the three keys changes (pid, ts, or reason). A null -> ts resolution on a retry flips it once; a final row keeps the cached keys (no final-row flip; the 128-game LRU is the only game bound).

## Network gate (AMENDMENT 2 (a))

`enrich(..., fetch=None)` uses the default network fetch ONLY when `get` is a local_state_capture_io.ReceiptGetter whose `client.session.session` is a `requests.Session` (the production path: local_state_capture.py ReceiptGetter over StateClient with its default session). Otherwise enrich returns the items unchanged: no new keys, no counter, no request. An injected `fetch=` always applies.

## Mandatory disclosures

- (a) wallclock is second-resolution, so any lag computed from it has a +-1 s floor.
- (b) it is ESPN's own play time, not a receipt; a play can appear on the scoreboard before the core API lists it (404), retried on up to 3 ticks in total.
- (c) null results carry a counted reason; the receipt time is never substituted.
- (d) the sequential fetch can lengthen a tick by about 2.0 s per league call and about 4.0 s per tick when both leagues are live, EXCEPT DNS resolution and a slow-drip body, which requests' timeout does not bound (per-request timeout = min(1.0, remaining / 2) because requests applies it per connect and per read phase, A3 (a)).
- (e) the cache is process-local; a restart refetches the current pid once per live game (and a same-ts refetch against a recovered baseline does not flip state_changed).
- (f) the lag figures from the session probe (NFL p50 44.1 s / p90 70.7 s, n=307; NCAAF p50 46.4 / p90 67.6, n=80) are pre-build measurements, not this row's result.
- (g) exec_quality_audit.py:52 will use the NFL source clock and counts a late null -> ts resolution as an extra play event.
- (h) the first post-adoption row of every live game flips state_changed once (the keys appear).
- (i) module counters() are not published to the heartbeat; TNF acceptance is read from rows.
- (j) capture_watchdog counts every drops_by_reason key as an error counter, so routine play_clock_http_404 / tick_cap / play_hold growth shows the state venue DEGRADED error_counter_growing during live NFL (report-only).
- (k) an internal exception restores the rows but keeps cache / hold changes made before it (an attempt can be spent without a written row).
- (l) the request cap applies in fixed item order: trailing NCAAF games may see tick_cap on a heavy Saturday (a rotating start is a follow-up).
- (m) a read timeout while streaming the body is labelled connect_error (requests raises ConnectionError there, not Timeout).
- (n) on Py3.10 a response_end_utc with 1-5 fraction digits fails fromisoformat, so the future check is skipped for that row (production writes 6 digits).
- (o) S535 dependency: whichever of S535 / S595 lands second re-checks that enrich time does not trip the S535 scoreboard deadline.
- (p) a JSON body nested deep enough to raise RecursionError is json_error (the pid attempt is recorded), not enrich_error every tick (A3 (c)).

## Deviations (with reasons; the first five RATIFIED by AMENDMENT 2 (c))

- Event id falls back to `game_key` (digits only) when `_start` is absent: the landed `unique_games` strips `_start` from every NFL/NCAAF item, so the spec's `_start`/competitions path alone gave `no_event_id` on every landed row (found by case 1b). `_identity` makes game_key = str(event id) whenever the event has an id; a surrogate key is refused as no_event_id.
- Memo date 2026-09-30 (spec body names -09-29); the orchestrator's dispatch named the -09-30 path.
- The import rides the existing try line, placed FIRST (`from ...ingame import espn_play_clock as play_clock; from domains.nfl...`) so an NFL adapter import failure still leaves `play_clock` bound. If the play-clock module itself failed to import, the except branch disables NFL/NCAAF entirely (they leave SPORTS_AVAILABLE); its imports are stdlib + requests + local_capture_client, all already loaded by the capture. local_state_capture_sources.py stays at 300 lines.
- Refusal counting: frozen pids (3 failed attempts) and non-live cached rows are written without re-counting their reason; gave_up is counted once. play_hold is counted once per call.
- no_play_id / no_event_id are NOT counted on the per-source drop counter (row reason + module counters() only). Counting them turned 12 landed tests red (test_state_capture_sources, test_state_capture_io, test_state_capture_fix_1q pin exact drop dicts for synthetic live NFL/NCAAF rows without lastPlay); a live row lacking a lastPlay id is an input property, not a fetch failure, and the row still carries its reason for the TNF check.
