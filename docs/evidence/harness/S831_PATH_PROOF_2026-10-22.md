## 1. Premise

The census (`docs/evidence/harness/QUALIFICATION_CENSUS_2026-10-20.md` section 4a) measured from the
receipts that since S767 (half-tick book repoll) the median book gap is about 2.45 s, about half of
all decisions are RESERVATION_INVALID, and coverage per qualified decision equals one book gap, so a
game with no rival covers about 47 pct. It left the code path UNPROVEN, with two candidates:
(A) `policy.consider` raising a cap refusal while the previous quote is pending, leaving
`last_reservation_end` stale; (B) the quote's `pulled` return skipping the update.

**Verdict: candidate (B) is the path. Candidate (A) is refuted for this game** (zero exceptions out
of `consider`, zero `insufficient_fresh_lifetime` returns).

## 5. Findings (counts from the scratch log)

### (i) The code path that produces RESERVATION_INVALID

Per-row sequence in `_prepare_inner`:

1. `forward_replay.py:48` resets `policy.last_reservation_end = None` on EVERY row.
2. `forward_replay.py:204` calls `policy.consider(...)`.
3. `forward_replay_policy.py:170` reserves room from `self.ledger.snapshot()`, which still holds the
   previous quote's two resting orders (they leave the in-memory ledger only on expiry,
   `forward_replay_policy.py:118-127,133`); the room loop in `quote_reservation.py:185-199` therefore
   grants 0 under global cap 1.
4. `make_quotes` returns `pull('capacity_exhausted')` (`quote_engine.py:169`), or
   `pull('state_change')` (`quote_engine.py:124`) inside the pull window.
5. `forward_replay_policy.py:177-178` returns `quote["pulled"]` BEFORE line 199
   (`self.last_reservation_end = issued_at + self.ttl`) runs, so the value stays None.
6. `forward_replay.py:209-210` books it as an abstention; the `finally` at `forward_replay.py:232-233`
   passes `policy.last_reservation_end` (None) to `Qualification.decision`.
7. `forward_replay_qualification.py:60` flags RESERVATION_INVALID (`reservation_end is None`).

| consider() outcome, in-window decisions | Count | RESERVATION_INVALID |
|---|---|---|
| returned None (quote submitted, line 199 ran) | 718 | 0 |
| returned `capacity_exhausted` (line 178) | 613 | 613 |
| returned `state_change` (line 178) | 109 | 109 |
| raised (candidate A) | 0 | 0 |
| returned `insufficient_fresh_lifetime` (line 184) | 0 | 0 |
| consider not called (abstention before line 204) | 0 | 0 |

At every one of the 1,440 decisions `last_reservation_end` entered `consider` as None (the line-48
reset), and after a submit it was exactly `at + 5.000000 s` for all 718 qualified decisions. The 722
invalid decisions all left it None.

**Why every second book:** a submitted quote rests until `end + cancel_delay`
(`forward_replay_policy.py:203`), where `end = now + expiry_s` (`:162`) and the defaults are
`expiry_s` 3 (`:87`) and `cancel_latency_s` 1 (`:86`): the logged pending life after every one of
the 718 submits was exactly 4.000000 s. The median book gap is 2.46 s, so the next book lands while
both orders still rest (refused, `capacity_exhausted`), and the book after it (about 4.9 s after
the submit) finds them expired and submits again. 715 of the 722 invalid decisions directly follow a
qualified one.

### (ii) Inside a still-pending previous reservation

- 670 of 722 RESERVATION_INVALID decisions (92.8 pct) had the previous quote's two orders still
  pending when `consider` ran: all 613 `capacity_exhausted` plus 57 of the 109 `state_change`.
- Remaining pending life at the 613 `capacity_exhausted` decisions: min 0.69 s, median 1.56 s,
  max 1.66 s (all > 0).
- The other 52 are `state_change` pulls with no order pending (refused by the state pull window,
  `quote_engine.py:123-124`, independent of the cap).

### (iii) How cut() credits coverage, and the counterfactual

- A qualified decision at `at` opens the interval `[at, min(at + 5, state_at + 15, reservation_end,
  window end, as_of)]` (`forward_replay_qualification.py:199-202`; `reservation_end = at + 5`).
- `Qualification.decision` calls `cut(g, at)` (`forward_replay_qualification.py:188`, body `:132-135`)
  on EVERY decision of the ticker BEFORE the validity test at `:195-199`. So a RESERVATION_INVALID
  decision ends the previous valid interval at its own `at` and opens nothing.
- `observe` also cuts on a non-live or `state_changed` state row (`:168-169`).
- Coverage is the merged union of the intervals (`:71`).

Cut calls on LADMIL intervals (1,866 logged):

| RESERVATION_INVALID decision, `capacity_exhausted` | 613 | 612 | 1,534.601 |

Recomputed actual coverage from the log: 1,692.276 s, which equals the receipt.

**COUNTERFACTUAL (arithmetic on the log, not a result):** if the 722 RESERVATION_INVALID decisions
did not call `cut()`, with every other cut kept (state-row cuts, qualified-decision cuts), the 718
intervals would merge to 3,165.933 s = 87.9 pct of the 3,600 s window. Skipping only the 613
`capacity_exhausted` cuts gives the same 3,165.933 s. It stays below the frozen 90 pct bar
(`forward_replay_qualification.py:18,74`) for this game. The refused books also never update the
replay's state the way a real re-quote would, so this is an upper-style arithmetic bound on the cut
rule alone, not a qualified coverage.

## 7. PROPOSED step (b) outline (not applied; needs its own dated day)

The interaction has two independent levers; step (b) must pick one, seal it, and show
byte-identical outputs on games it does not touch.

1. **Cut rule:** a decision that fails ONLY RESERVATION_INVALID because the policy refused to quote
   while its own previous quote still rests (`capacity_exhausted` with a pending order of the same
   game) does not end the previous interval; the previous interval keeps its own bound
   (`reservation_end` = issued_at + ttl, `at + BOOK_AGE_S`, state age). Touches
   `forward_replay_qualification.py:188` and the `decision()` signature, or the value passed at
   `forward_replay.py:232-233`.
2. **Reservation carry-over:** when `consider` returns `capacity_exhausted` and the occupying orders
   are this game's own resting quote, report the still-live reservation end instead of None
   (`forward_replay_policy.py:177-178` vs `:199`, reset at `forward_replay.py:48`).
