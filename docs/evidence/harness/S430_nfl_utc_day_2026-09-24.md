## Receipt and row schema

fetch_schedule_utc_day requests the previous date first, then the requested date.
It applies the UTC window to previous-date rows; each retained previous row adds
listed_on_previous_us_date and each previous row whose start parses outside the
UTC day adds previous_us_date_other_day (see FIX 1b for unparseable starts).
Requested-date rows retain the writer's existing
validation. Within-payload duplicate refusals remain intact.

Rows add schedule_query_date (YYYYMMDD). Cross-payload equal starts produce one
row and espn_listed_twice; conflicting starts produce one event_start_conflict
refusal with sorted start_texts. Rows sort deterministically with fixed query
provenance. Swapping which query contains an event changes source evidence;
permuting event order within either query does not change the semantic result.

The receipt preserves the requested-date url, request_start_utc, http_status,
response_sha256, response_bytes and any error_type. response_end_utc is the
maximum parsed end of the two requests. query_receipts maps each YYYYMMDD to
its complete original receipt. kept_from maps each game_key to the date of its
deterministic retained row. Thus the existing writer cutoff covers both requests.
The seven-field schedule output is unchanged. MLB and tennis use their original
fetch path even when the writer flag is supplied; direct calls to the new API
for either sport raise ValueError.
