## Build decisions (flagged for the verifiers)

1. X = 2026-10-01. Per AMENDMENT 2 (i), commit A (PREREG_M2.json alone) carries committer UTC date 2026-09-30, so X = commit UTC date + 1. The code enforces commit date < X; meeting "+1" exactly is the lander's step. Commit A is never amended or rebased afterwards, because %ct is the committer date and a rewrite would move it past X.
2. An 'unavailable' state or book source makes every tick of that sport source_unavailable (spec item 1, applied literally). The scorer marks an absent D or D+1 shard 'unavailable', so a real night with an absent shard would read out entirely as source_unavailable. The E2E and construct nights therefore carry an empty D shard. This is an open question for the verifiers.
3. The seal pins 10 files: the 8 of AMENDMENT 1 item 2, m2_readout_history.py (it holds the cell and verdict rule) and anchor_projection_stats.py (AMENDMENT 2 (a): its cboot produces every CI and so decides the headline verdict). It also checks the S542 verdict artifact's LF sha on disk, and a difference refuses identity_mismatch.
4. prereg_not_production exits 3 (AMENDMENT 1 item 3), not 2 as the case-16 text says. wnba gets m2_not_defined (AMENDMENT 9), not wnba_constants_unfitted. MLB is INSUFFICIENT by declaration, with no 2027 rule.
5. HISTORY lists the <YYYY-MM-DD>.json files beside the --night (a directory listing only). In production the night must resolve inside docs/evidence/forward/scoreboard/, else night_not_production (exit 3). A date is marked RECONCILE_FAILED when out-dir/<D>.json carries that status.
6. The anchor-book check runs on every mlb / nba tick, fresh ones included, before the fresh_anchor rule. book_mid_refused is counted once per distinct (receipt, home_abbr, away_abbr) pair, through the _mid cache.
7. A no-Stream game (no live state entry) gives no_known_state. source_unavailable is reserved for unavailable sources, so that case 7 holds.
8. Refusal of an effective date that is not ISO or is later than 2026-10-19 is effective_date_invalid (exit 3).
