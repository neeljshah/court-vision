## Premise (Q8) -- re-measured, HOLDS

`wp_diagnostics.reliability` binned by `min(9, int(p * 10))`; `scoring.ece` and
`calib_decomp.decompose` bin by `np.linspace(0, 1, bins + 1)` edges with `[lo, hi)`
intervals and a closed last bin. They disagree on predictions landing exactly on the
0.1 grid, because `0.6 * 10 == 6.000000000000001` while `np.linspace(0, 1, 11)[6] ==
0.6000000000000001` -- the legacy rule puts p = 0.6 in bin 6, the edges put it in bin 5.

## Change

- `scripts/platformkit/calib_decomp.py` (additive): `bin_edges(bins=10)` -- the one
  edge array -- and `bin_index(prob, edges)`, which reproduces the
  `decompose`/`ece` `[lo, hi)`-plus-closed-last-bin semantics exactly via
  `searchsorted(..., side="right") - 1`. `decompose` now calls `bin_edges(bins)` in
  place of its own inline `np.linspace` (same value, so the sharing is structural
  rather than coincidental).
- `scripts/platformkit/wp_diagnostics.py`: `reliability(ticks, edges=None,
  legacy_bins=False)`. `edges` defaults to `bin_edges(10)`; `legacy_bins=True` keeps the
  old `min(count-1, int(p*count))` assignment reachable. Bin LABELS are formatted from
  the edges and are byte-identical to the old `index/10` labels at 10 bins, so no reader
  of `wp_diagnostics_*.json` sees a renamed key or a changed bin string (B2).
- `scoring.ece` is NOT touched: its primary branch delegates to `kernel/` (human-gated)
  and its fallback branch already builds the identical `np.linspace` array. The new test
  asserts `bin_edges(10) == np.linspace(0, 1, 11)` so a drift there breaks a test.

The only behaviour that changes is grid-boundary rows moving to the bin the summary
statistics already used. That IS the fix; no threshold, bar or gate value moved (B10/Q3).
