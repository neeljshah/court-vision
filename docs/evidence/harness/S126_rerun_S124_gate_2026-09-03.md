## 2. S124's remaining half -- the second gate on the served feature set

### 2a. What the row asked for, and the one deviation

The row asks for a gate in `run()`/`sweep()` refusing a candidate column that tracks the label,
plus a frozen-grammar membership assertion. The natural instinct -- "put the ad-hoc feature
through `assert_label_blind`" -- **cannot bind here, and shipping it would have been a
fall-through gate (B3)**: `assert_label_blind` permutes the label and REBUILDS, and a column
handed to `run(features=...)` or `sweep(hypotheses=...)` is already materialised, so there is
nothing to rebuild and the comparison is a tautology that always passes. The binding statement
of the same contract at tick grain is the S124 row's own rule, and that is what
`assert_column_blind` implements. This is a deliberate deviation from the literal instruction
and is reported as one rather than hidden behind a call that could never fire.

### 2b. The change (2 helpers, 2 call sites)

`scripts/platformkit/foundry/ingame_guards.py` (178 lines):

- `AdHocFeature(AssertionError)` -- a served feature outside the frozen grammar.
- `gate_features(served, frozen, allow_adhoc=False) -> list` -- the SUBSET assertion. Returns
  the ad-hoc names; **on the frozen path it returns `[]` and nothing else runs**, which is why
  every landed screen re-runs byte-identically.
- `assert_column_blind(values, labels, column) -> bool` -- raises `TickTimeLeak` when the column
  DETERMINES the tick's label (every one of its distinct values maps to exactly one label) AND
  it carries no more distinct values than the label does. The distinct-value ceiling is what
  keeps an honest continuous column out of the rule: a continuous column determines the label
  trivially, one row per value. It returns **False when the rule did not bind**, which is
  honest, not a pass. The row's "per-game variance zero AND the per-game value tracks the game's
  label" case IS this rule whenever the label is constant within a game, which it is on every
  corpus this tier runs on.

`ingame_screen.run(..., allow_adhoc=False)` gates `features=` against `FEATURES`, the frozen MLB
grammar, and puts each opted-in ad-hoc column through `assert_column_blind`.
`ingame_screen_nba.sweep(..., allow_adhoc=False)` gates the served hypotheses against
`{semantic_hash(h) for h in ingame_grammar_nba.enumerate_hypotheses()}` -- the frozen 576 -- and
checks each opted-in ad-hoc hypothesis's materialised column the same way.
