## Verdicts

### patched/codex_pipeline.sh -- ACCEPT WITH CORRECTIONS (do not install as written)

Good: the awk `match($0,/wt=a[0-9]+/)` home extraction is a real bug fix. The live sed
(`sed -E 's/.*wt=(a[0-9]+).*/\1/'`) does not substitute when the line has no `wt=aN`, so it echoes
the WHOLE line -- visible in the live log right now:
`build EXIT:0 but NO COMMIT in DISPATCHED run=1788813976878680300 tag=s311_ops wt=ops_lane ... for S311`.
Also good: verifier binding to SID/home/SHA, EXIT read only below the last DISPATCHED, empty log
treated as NONE, atomic per-build claims, ORPHAN surfacing. No bashisms; POSIX-clean for sh.exe.

C1 (BLOCKING -- silent total stall). `build_sha()` requires a canonical `^SHA: <hex>` or
`^Final SHA: <hex>` line after the last DISPATCHED, else `continue`. That line does not exist:
`grep -acE "^SHA: [0-9a-f]{7,40}" /c/Users/neelj/AppData/Local/Temp/cx_*.log` = 0 across every log,
while `^VERDICT:` lines ARE present -- so hidden_launch2's FINAL_LINE re-emitter works; builders
simply never print a hex SHA. The current build_prompt.txt in fact instructs the opposite:
"finish with the report and the line 'SHA: NOT CREATED (sandbox); files ready for lane_commit'".
Under the sandbox, builds EXIT:0 with NO commit at all; the sha appears only after lane_commit.py
runs. Live proof from pipeline.log today: three `NO COMMIT ... orchestrator` lines (S293, S304,
S311), and pipeline_g.log's `build done G305 wt=a6 sha=68fa15009 -> verify` -- that sha came from
`git log master..HEAD`, the very code path the patch deletes. Installed as written, the S pipeline
would never dispatch a verifier again, and would log nothing while doing it.

Corrected lines -- replace

        bd=$(last_dispatched "$f"); [ "$bd" -gt 0 ] || continue
        sha=$(build_sha "$f" "$bd"); [ -n "$sha" ] || continue
        home=$(awk -v n="$bd" 'NR==n { if (match($0,/wt=a[0-9]+/)) print substr($0,RSTART+3,RLENGTH-3) }' "$f")
        [ -n "$home" ] || continue

with

        bd=$(last_dispatched "$f"); [ "$bd" -gt 0 ] || continue
        tail -n +"$bd" "$f" | grep -aq "^EXIT:0" || continue
        home=$(awk -v n="$bd" 'NR==n { if (match($0,/wt=a[0-9]+/)) print substr($0,RSTART+3,RLENGTH-3) }' "$f")
        [ -n "$home" ] || continue
        sha=$(build_sha "$f" "$bd")
        [ -n "$sha" ] || sha=$(git -C /c/Users/neelj/nba-track-$home log --format=%h -1 master..HEAD 2>/dev/null)
        if [ -z "$sha" ]; then
          note_once "nocommit.$sid.$bd" "build EXIT:0 but NO COMMIT in $home for $sid -- run lane_commit.py"
          continue
        fi

C2 (BLOCKING, and the reason C1's ordering matters). `build_sha` only prints when it reaches
`EXIT:0`, so it was implicitly the EXIT gate. Adding the git fallback WITHOUT the explicit
`tail -n +"$bd" | grep -aq "^EXIT:0"` line above it would dispatch a verifier against a stale
master..HEAD sha WHILE THE BUILD IS STILL RUNNING. The corrected block restores the gate first.

C3 (BLOCKING -- restores the live READY TO LAND + empty-land-log behaviour). Replace the whole
`ACCEPT|CLOSED)` arm (the claim_dispatch land call and the land-observation block below it) with:

      ACCEPT|CLOSED)
        # 2026-09-07: codex lander disabled (sandbox cannot spawn Git Bash); Opus agents land.
        if [ ! -f "$llog" ]; then
          echo "$(date -Is) $sid $vr sha=$sha -> land" >> "$LOG"
          echo "$(date -Is) READY TO LAND $sid wt=$home (orchestrator lander; codex lander disabled 2026-09-07: sandbox cannot spawn Git Bash)" >> "$LOG"

Rationale: with the lander disabled, the land claim / BASELINE / EXIT observation is dead code.
Keeping `[ ! -f "$llog" ]` reproduces the live idempotency exactly (the empty log is the sentinel).
Note the patched code would not have crashed on the empty log (`[ -s "$llog" ]` guards it) -- it
would simply have called codex-land, which is what must not happen.

C4 (non-blocking). `note_once` markers under `$STATE` are never pruned and $T survives reboots. Add
a runbook line to `rm -rf $T/cx_pipeline_state` when deliberately re-running a row.

### patched/dispatcher.sh -- ACCEPT WITH CORRECTIONS

POSIX-clean (`IFS='|' read` via heredoc, `${H#a}`, `case`, mkdir locks -- no bashisms). Claim-by-
rename plus atomic `mkdir` receipt is the right shape: ready/<row> -> claimed/<SID>.ready happens
BEFORE `mkdir receipts/<SID>.STARTED`, and codex-build runs only after both. Re-running after a
crash between the two yields exit 4 ORPHAN, never a duplicate build; re-running after a crash past
STARTED yields "ALREADY STARTED" and exit 0. The per-home `mkdir "$LOCKS/$H"` admission lock makes
the concurrent case single-winner (verified by the matrix's concurrent-claim case: build called
exactly once). Idempotency verdict: correct.

C8 (BLOCKING). The orphan pre-scan walks EVERY entry in claimed/ and exits 4 for any of them. One
crashed row therefore wedges every home permanently, including homes with nothing to do. Scope the
scan to this home's own claim, or make it a warning. Corrected block:

    for row in "$CLAIMED"/*; do
      [ -f "$row" ] || continue
      sid=$(basename "$row"); sid=${sid%.ready}
      [ -d "$RECEIPTS/$sid.STARTED" ] && continue
      echo "dispatcher: ORPHAN $sid (claimed without STARTED); reconcile, do not requeue"
      [ -f "$RECEIPTS/$sid.HOME.$H" ] && exit 4
    done

(Simplest alternative: record the home in the claim name, `claimed/<SID>.<home>.ready`, and exit 4
only when the orphan's home is $H.)

C9 (BLOCKING for behaviour parity). Row selection is `for candidate in "$READY"/*; ... break`, i.e.
glob order, which is lexical: S1000 sorts before S308, S297 after S2. sweep_queue.txt was strict
FIFO by line. Either name rows with a zero-padded sequence prefix (`0001_S310`) and document it, or
select by mtime:

    row=$(ls -1tr "$READY" 2>/dev/null | head -1); [ -n "$row" ] && row="$READY/$row"

C10 (non-blocking). `mv "$row" "$claimed"` silently overwrites an existing claimed/<SID>.ready.
Harmless while the lock is held and SIDs are unique, but one line closes it:
`[ -e "$claimed" ] && { echo "dispatcher: duplicate SID $SID already claimed"; exit 4; }` before the mv.

C11 (non-blocking). `DISPATCHER_CRASH=after_claim|after_started` are test hooks living in production
code. Acceptable (inert without the env var) but note them in the runbook so nobody sets them.

### patched/pod_run -- ACCEPT WITH CORRECTIONS

safe_path is correct on every case the brief names. It rejects `..` and `.` components, absolute
(`/x`), drive letters (`C:/x`), backslashes (`a\b`), and anything outside `[A-Za-z0-9._/-]`; and --
checking every ANCESTOR, not only the leaf -- symlinks, NTFS reparse points
(`st_file_attributes & FILE_ATTRIBUTE_REPARSE_POINT`) and hardlinks (`st_nlink != 1`). `--ship`
additionally requires existence; `--fetch` correctly does not. Fetch targets are re-validated AFTER
`mkdir -p`, closing the TOCTOU window. tar AND ssh statuses are separated via `PIPESTATUS` captured
immediately after the pipeline (tar rc -> exit 4, ssh rc -> exit 5); the original checked only
`${PIPESTATUS[0]}` and treated rc<=1 as success. Fetch runs only after the sentinel parses and
`remote_rc -eq 0`, and a fetch failure is fatal (exit 6). Timeout is exit 124, not 0. The main-tree
fallback (`[ -d "$WT" ] || WT=/c/Users/neelj/nba-ai-system`) is gone and `aN` is required. All correct.

The `CMD="$*"` defect is genuinely fixed at the root: argv is JSON+base64 encoded locally and
decoded remotely into `subprocess.run(argv)`, so `python -c "import x; print(1)"` survives instead
of being re-split by the remote shell. That is the exact bug the bootstrap agent hit today.

C12 (BLOCKING). `DATA_RO=${POD_DATA_RO:-/workspace/data-ro}` combined with
`ssh_run "... test -d '$DATA_RO' && ln -s '$DATA_RO' '$R/data'"` means EVERY pod_run exits 5 at
setup if /workspace/data-ro has not been provisioned. The memo's own NOT VERIFIED list admits it was
never checked, and no session touched the pod today. Until a read-only data root exists, default to
the path the original used:

    DATA_RO=${POD_DATA_RO:-/workspace/nba-ai-system/data}

Flip it to /workspace/data-ro in a separate, pod-verified step. (The astra note is right that a
writable data symlink is a real exposure -- but a launcher that cannot launch is worse.)

C13 (BLOCKING). The 50 GB volume guard was dropped. bin_copy did an 8 MB write probe, then
`du -sm /workspace` with a hard stop at 47000 MB and a warning above 3 GB for /workspace/wt -- that
guard is shared with the tracking session. The patch also gives every invocation a FRESH
`$REMOTE_ROOT/$H/jobs/<job-id>` root and re-ships the whole python tree into it with no pruning, so
consumption now grows monotonically. Re-add, after the `ssh_run` helper is defined and before the
ship:

    USED_MB=$(ssh_run "du -sm /workspace 2>/dev/null | cut -f1")
    echo "POD /workspace ${USED_MB} MB used of 50000"
    [ "${USED_MB:-0}" -lt 47000 ] || { echo "POD VOLUME ABOVE 47 GB -- not running (tell the tracking session)"; exit 3; }
    ssh_run "ls -1dt '$REMOTE_ROOT/$H'/jobs/* 2>/dev/null | tail -n +11 | xargs -r rm -rf"

C14 (non-blocking). On timeout the script exits 124 without printing the remote log, so a hung job
leaves no diagnostic. Move the tail above the timeout exit:

    [ "$done_seen" -eq 1 ] || { ssh_run "tail -n 40 '$LOG'"; echo "pod_run: timeout job=$JOB_ID"; exit 124; }

C15 (non-blocking, behaviour note). The remote command is now argv, not a shell string. Callers
passing shell syntax INSIDE one argument (`pod_run a1 -- "cd x && python y"`) break; callers using
`bash -c '...'` or plain argv are fine -- every invocation in build_prompt.txt, codex-verify and
codex-land is `-- python -m pytest ...`, so nothing in the prompt set regresses. Local redirections
were always local, before and after. Also `--` is now mandatory (bin_copy allowed
`pod_run a1 python x.py`); say so in the prompts if any lane relies on the old form.

C16 (non-blocking). `exit "$remote_rc"` can collide with 124 (timeout) or exceed 125. Clamp or remap
if a caller distinguishes them.

C17 (non-blocking). `printf -v inner_q '%q'` is bash-LOCAL quoting handed to the REMOTE shell. It is
safe for this particular string (no control characters, so bash emits backslash escaping rather than
`$'...'`, which dash would not parse), but it is fragile by construction. A base64 round trip for
`inner` too would remove the whole class of bug. Not required now.
