## Task 1 -- stale agent worktrees under .claude/worktrees/

Population: 35 worktrees (22 `agent-*`, 13 `wf_*`).

Content test used, and why it is not `git cherry`: every one of these branches sits
1,072-3,156 commits "ahead" of master because `origin/master` was force-rewritten on
2026-08-03. `git cherry master <tip>` therefore has to patch-id thousands of commits
per branch and does not terminate in usable time (measured: 1 tip completed in >2 min,
25 unique tips required). Substituted an equivalent, cheaper test: the branch tip's
root tree SHA is looked up in the set of all 3,540 unique tree SHAs reachable from
master (`git log --format=%T master`). A hit means the tip's full file state is
byte-identical to a state already preserved in master's history, so nothing is lost by
removing the worktree or its branch.

The substitution was afterwards validated against the real thing, not just argued: the
abandoned `git cherry master <tip>` sweep was left running and did complete, covering
all 25 unique tips (931-2,923 commits each). It agrees with the tree test on 25/25.
Exactly one tip has a non-equivalent commit -- `093d05375` (`wf_1f1e8c90-97b-64`) at
`+1` -- and that is the one worktree the tree test flagged TREE_UNIQUE and kept. All 24
others, including all 8 removed, return **0 commits marked `+`**, i.e. `git cherry
master` is all `-`, which is the removal criterion this lane was given verbatim. So the
8 deletions are backed by the specified test itself, not only by the proxy.
