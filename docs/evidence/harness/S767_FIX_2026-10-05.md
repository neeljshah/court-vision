# S767 fix: tick grid re-anchors after a host pause (PAPER ONLY)

Branch `cxp/S767-2026-10-05`, parent 17d19e8fd (candidate REJECTED by the Opus verifier tier).

## Defect (reproduced by the verifier tier and confirmed by reading the code)

`capture_repoll.next_tick` only ever added `focus_tick_s` (5 s) to `state["tick_grid_start"]`
and never re-anchored it. `local_capture_runner` (line 176) sets
`deadline = tick_grid_start + tick_s`. After a host pause the grid sat in the past, so every
deadline had already expired: `guarded()` carried every request, and the loop fired catch-up
ticks with zero requests and zero spacing. At 3 scheduled games with one clock jump at
t=250 s, a scheduled game was dropped (`cadence_p90_over_7_for_3_ticks`), unscheduled games
churned into its slot, and the selected-ticker gap reached 87 / 102 / 132 s for pauses of
15 / 30 / 60 s. On master there are no drops and the gaps are 22 / 37 / 67 s. A 30 s host
pause was measured live on 10-05.

## Fix (`scripts/platformkit/ingame/capture_repoll.py`)

```
-    state["tick_grid_start"] = state.get("tick_grid_start", started) + tick_s
-    return max(0.0, state["tick_grid_start"] - now)
+    grid = state.get("tick_grid_start", started) + tick_s
+    if grid + tick_s <= now:  # host pause: no catch-up ticks with an expired deadline
+        grid = now
+    state["tick_grid_start"] = grid
+    return max(0.0, grid - now)
```

When a whole tick is missed, the grid re-anchors to now. A sub-tick overrun keeps the nominal
grid, so `test_delayed_work_keeps_nominal_grid` still passes unchanged. The runner is
unchanged, so its deadline is still `tick_grid_start + tick_s`.
