# S310 preregistration: NBA tail beta-offset calibration screen

## Fixed protocol

- Contract: `docs/evidence/tracking/VERIFIER_CONTRACT.md`, sections B and Q1-Q9.
- Input: `data/cache/inplay_odds/nba_checkpoints_full.parquet`, one tabular store, 2829826 bytes, 465249 rows and 1593 game clusters; resolution is not applicable. The preflight prints columns and the first three game ids.
- Binding premise remeasurement: the frozen raw `market_prob` band 0.01 through 0.05 contains 9226 ticks from 649 game clusters and 29 positive-outcome clusters. The 271154 zero-clock rows are tabulated only as terminal-status context; no row is excluded on outcome or terminal status.
- Unit: exactly one evaluator state per input tick. Its stable key is `game_id:ts:row_index`; state keys are unique before `cpcv_evaluate` is called. The game id remains the cluster id in the archives.
- Outer route: `scripts.platformkit.eval_gate.cpcv_engine.cpcv_evaluate`, two frozen chronological season groups, one test group, shared purge, and a symmetric one-day nonzero embargo. Each prediction is an evaluator record. The callback additionally admits only training game dates strictly before every scored game date.
- Baseline: `recal_null` is a logistic calibration of raw `market_prob`, with logit(raw probability) as its sole feature, fit only on the eligible outer training rows. No fitted value or outcome from the outer scored season enters this fit. If a fold has no strict-past train rows, baseline and candidate equal raw probability.
- Frozen tail selection: after baseline prediction, the only altered states are low `0.01 <= recal_null <= 0.05` and high `0.95 <= recal_null <= 0.99`. This uses baseline probability only, never outcome. Outside those bins, candidate equals baseline byte-for-byte.
- Candidate: within the frozen tail, fit a ridge-100 beta-shape residual to nested OOF baseline values from strict-past inner date blocks. With `z=logit(recal_null)`, the candidate is `sigmoid(z + r)` where `r=b0 + b1*log(raw_prob) + b2*log(1-raw_prob)`. The ridge is centered at zero, so `b=(0,0,0)` is exactly the identity candidate. Fewer than two inner outcome classes also yields the identity candidate. No hyperparameter is selected after inspection.
- Inner calibration: the outer training season is split into five ordered distinct game-date blocks. Inner OOF baseline predictions for a block are fit only on earlier blocks, after the same one-day calendar embargo. The beta residual is fit only to those nested OOF rows that are in the frozen baseline tail; the outer callback refits its baseline on eligible outer training rows and applies that residual without admitting an outer scored label.
- Scoring: epsilon is 1e-15. Primary metric is tail binary log loss. Guard metric is global tick-weighted Brier. Archive every evaluator record's state key, cluster id, timestamp, probabilities, labels, tail bin, log-loss pair, Brier-loss pair, split id, and train count. Bootstrap resamples game clusters with replacement 10000 times, seed 905, retaining each sampled cluster's full tick denominator.
- Fixed reports: low bin, high bin, combined tail, and global metrics each have paired 95 percent percentile intervals. Low/high two-sided bootstrap sign probabilities receive Holm adjustment; no bin is labelled favorable unless its adjusted sign probability is below 0.05 and its paired lower bound is positive.
- Acceptance bar: the combined-tail log-loss paired 95 percent lower bound must exceed 0, and the global Brier paired 95 percent lower bound must be greater than -0.0005. This is a tail-conditional screen only. The prior S272 all-ticks reference `-0.000036668` is not moved or reused as an acceptance bar. The S272 trainable-tail oracle cap `0.002534` is reported as a precision limit, not relabelled as a global success.
- Scope: no deploy, flag, registry, ledger, or source-store write. This screen is uncharged; no shared ledger is read. Sign convention everywhere: improvement equals baseline loss minus candidate loss; positive means candidate better.
- Outputs: `docs/evidence/harness/S310_tail_beta_offset_2026-09-07/memo.md`, `summary.json`, `paired_losses.csv`, `probabilities.csv`, `train_keys.json`, and `clips.json`, plus `tests/platformkit/test_s310_tail_beta_offset.py`.
