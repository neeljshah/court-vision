## B. What remains live

### B1. Can an existing receipt accept a zero-byte or unparseable sealed artifact?

On the existing-receipt branch, the artifacts are never read:
- paper_desk_actions.py:162 calls accepted_receipt(day, row, artifacts=False);
- receipt() skips the artifact loop when artifacts is False (paper_desk_evidence.py:104);
- :136 sets receipt_accepted True;
- the row decision is night_skipped / exists_one_attempt_or_not_due (:164-165).

night_skipped is benign, not success (paper_desk_attention.py:76), so the tick never labels this a
success. receipt_accepted only clears night_failure_state (:77), which is irrelevant once a record
exists. census_day also uses artifacts=False (:252). So a bad artifact is "accepted" only in the
narrow receipt_accepted sense. The real gap is in the one place the artifacts ARE read, the
post-run branch at :220-225, in two ways:
- (i) an oversize or nonfinite artifact raises, giving step_exception and no audit (section 0);
- (ii) a RAN step's counted artifact_empty / artifact_unreadable stays on the outcome only. The row
  gets decision night_partial / night_complete with refusals {} and classifies as SUCCESS, so a
  zero-byte artifact of a RAN step IS reported accepted.

Minimal fix (no queue, no per-tick re-parse):
- (a) receipt() reads night artifacts through document() with a per-prefix cap: scoreboard/ 32 MiB,
  others 8 MiB, the S718 pattern. Any ValueError from document() becomes a counted
  artifact_too_large / artifact_unreadable on that outcome, never a raise.
- (b) accepted_receipt counts read-loop artifact refusals from non-KILLED steps into
  row["refusals"]["night_artifact_refused"] = n. receipt_accepted is True only when n == 0. The key is
  not in the night success/benign sets, so the row classifies as attention.
- Digest mismatch, invalid_night_record and duplicate_night_step still raise (fail-closed, unchanged).

## C. The S602 conflict and why the narrowed design cannot repeat it

The S602 contract is pinned by tests/platformkit/ops/test_paper_desk_legacy_nights.py:34-36:
`assert (row["decision"], row["reason"], row["refusals"]) == ("night_noncanonical_as_of",
"owner_intervention_required", {"night_noncanonical_as_of": 1})`.
The S602 row says: "an explicit dated legacy_noncanonical exclusion list ... never a rerun".

The reverted 6e8686491 broke it in two ways:
- it replaced the lookup's `except ...: pass` with `row["refusals"]["legacy_night_lookup_invalid"] = 1`;
- it added `night_steps_absent` for steps=[]. steps=[] fixtures are master contract in
  test_paper_desk_legacy_nights.py:20,89, test_paper_desk_s520_night2.py:30,
  test_paper_desk_r3_runtime.py:23 and test_paper_desk_r4_runtime.py:50.

The four guard files and what each guards (.planning/codex_push_2026-10-02/out/compose_report.md:343-346):
- legacy_nights: the S602 exact-as_of list;
- s520_night2: an exit-zero night reads night_complete / receipt_observed / {};
- r3_runtime: census on a PARTIAL night;
- r4_runtime: night_partial clears the failure backoff, and a non-canonical record does not.

The narrowed design cannot violate S602, for three reasons:
- the legacy branch (paper_desk_actions.py:141-153) is untouched;
- the as_of check (paper_desk_evidence.py:77-78) raises before the step loop, so a legacy night
  never reaches the artifact counter;
- steps=[] still parses, with no empty-steps refusal and no new receipt() return key.

A night with no artifact read refusal gives a row byte-identical to today. Legacy nights are never
looked up for revision, never revised, never re-run.

## F. Coordinator follow-up: qualification/2026-10-07.json was 0 bytes mid-run (14:43Z 10-08)

The 0-byte file is expected. It is the qualification child's exclusive date claim, not a torn write
and not an S711 regression.

How the producer writes the file (scripts/platformkit/ops/forward_qualification_daily.py):
- At run start, `_reserve(args.out)` (:58-70, called at :197) creates the canonical path with
  `open("x")` and closes it EMPTY. If the path already exists, it claims <D>.rN.json instead.
- The real content is published only at the end. `_atomic(target, payload)` (:40-56, called at
  :276 and :291) writes a sibling NamedTemporaryFile, fsyncs it, then calls os.replace. On an
  exception the claim is unlinked (:277-279).
- So for the child's whole wall time the canonical path is 0 bytes. On 10-06 that was 559 s.
  Rename publication is atomic, but the reserve-then-replace shape is byte-frozen by S485.
- S711 did NOT change this file: its last commit is a2b9396e0 (S485). S711 added the post-kill sweep
  paper_night_attempt.drop_empty_claims (:82-110). That sweep runs ONLY for a KILLED qualification
  with kill_survivors 0. A sleep, crash or reboot mid-run leaves the 0-byte claim in place.

What each reader does with a 0-byte claim mid-write:
- Tick night decision: never reads it. nights/<D>.json is written only when paper_night finishes,
  so the tick is in a "no record" branch (paper_desk_actions.py:162-165 is not reached). Any launch
  meets the runner lock and exits 3 runner_busy, which gives night_deferred with refusals {}
  (pinned by test_paper_desk_s520_night2.py case11). Result: no accept, no refuse, no crash.
- Existing-receipt decision: not reachable mid-run, for the same reason. After the run, receipt()
  reads only artifacts the night record declares.
- paper_night's own record: for a RAN qualification, paper_night.py:157-161 replaces the declared
  path with the stdout "artifact" path, the file the child actually published (possibly .rN).
  So the record names a non-empty file.

When a 0-byte qualification file IS recorded, the outcome depends on the step:
- KILLED step: S711 records step_killed + artifact_empty and the claim is swept
  (paper_desk_evidence.py:99-103). Counted, row PARTIAL.
- RAN step whose recorded artifact reads as 0 bytes: receipt() counts artifact_empty
  (paper_desk_evidence.py:112-116). This is the remaining defect (ii) of B1: the row still reads
  night_partial / night_complete with refusals {} and classifies as SUCCESS. Accepted silently.
  The narrowed spec turns this into attention (night_artifact_refused).
- Before S711 (09-30, 10-01): a crash. JSONDecodeError gave refused step_exception, as in section 0.

The leftover hazard is an interrupted (not KILLED) attempt:
- The canonical 0-byte claim survives, and the retry claims and records <D>.r1.json
  (forward_qualification_daily.py:66-70).
- The tick receipt is correct, because it reads the recorded .r1.
- Path-based readers still meet the empty canonical file:
  - coverage_receipt reads qualification/<D>.json and counts qualification_unreadable
    (RED_TESTS_2026-10-06.md:41, the 09-30 case);
  - paper_dashboard_data.py:246-247 globs qualification/*.json.
- These are refusals or omissions, not acceptances. NOT VERIFIED for forward_week_report revision
  selection on a 0-byte canonical file.
- This is outside the narrowed S712. Candidate row text for the dispatcher: "an interrupted
  qualification attempt leaves its 0-byte canonical claim; sweep it on the next attempt under the
  runner lock (same rule as drop_empty_claims, any prior attempt), never by a reader".
