## How it runs

- Runner: `python -m scripts.platformkit.ops.system_fault_matrix --root <scratch dir> [--case N ...] [--json out.json]`. Exit 2 when any case is ERROR.
- Cases: scripts/platformkit/ops/system_fault_cases_{capture,capture_b,tick,tick2,tick2_b,night,night_b,night2,night2_b,shadow,ops2,ops2_b}.py.
- Test: tests/platformkit/ops/test_system_fault_matrix.py runs each case in tmp_path and pins PASS or DEFECT; the row that fixes a DEFECT moves it to PASS.
- Live guard (scripts/platformkit/ops/fault_matrix_guard.py): an audit hook, armed only while a case runs, refuses any write, rename, delete, mkdir, chmod, utime, truncate, link or sqlite open under the live-state directories (live checkout data/, docs/evidence/forward/, vault/), and any child whose argv (list or Windows command string) or cwd names them. Children a case starts are guarded too (limits below): the runner puts fault_matrix_site/ (a sitecustomize.py) on PYTHONPATH, the child arms the same hook and records each refusal in a sink file the runner reads. Any refusal makes the case ERROR. It fired 0 times in this run.
- Inputs: committed 50-line gzip slices of the real 2026-09-29 mlb/nfl books and state shards (tests/platformkit/ops/fixtures/fault_matrix/), the tracked 2026-09-29 schedules and seals, and fake capture children. Components are driven through their real CLIs or their injectable seams (clock, RAM, process list, run).
- Wall time: about 2 minutes for all 34 cases.
