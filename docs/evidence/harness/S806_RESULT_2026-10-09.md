Why the bytes cannot move: (1) the popped keys are read only inside _prepare (adapters + validation); everything after
reads ticker, sport, close_time, game_key / event_ticker and _at (link_fill -> index_kalshi_events reads flat keys only);
release=False (every caller but run_files) leaves the caller's rows untouched. (2) an interned Decimal has the same sign,
digits and exponent, so repr, arithmetic, hashing and ordering are identical. (3) the memo maps a live size object to the
result of the same expression; a raising size is not cached and raises again. (4) high / low / count are the same
reductions over the same value sequence, started at Decimal(0)'s adjusted() = 0 and exponent = 0 as the list was.
One ordering difference, stated: the old code materialised every value before parsing any; the stream interleaves. Only an
exception other than ValueError from str() or a non-dict book could surface in a different order; no such input reaches it.
