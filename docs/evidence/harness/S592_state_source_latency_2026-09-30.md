## MANDATORY DISCLOSURES
1. MLB = statsapi feed/live REST polling; the push socket (7.0-7.8 s) is NOT in this receipt (S593).
2. Our MLB poll gap p90 (48.5 s) is queueing in our tick, not the source: play lag conflates source delay, CDN cache age and our poll gap, and source_delay_lb is only a lower bound. Football live-row requests usually start early in the tick (frozen tick_offset p50 nfl 1.5 s, ncaaf 4.0 s) but late in a tail (p90 nfl 41.0 s, ncaaf 53.0 s). The critic's 40-47 s p50 on 09-25 was over ALL rows, not live rows, and is NOT reproduced on live rows; so the football wallclock lag (p50 50.0 / 46.5 s) is mostly ESPN scoreboard publication plus our 10 s poll, with tick order adding to the tail only.
3. NFL/NCAAF/NBA/WNBA/soccer/tennis ESPN scoreboard rows have NO source clock: their lag comes only from the ESPN core-API play wallclock join (public GET, one game at a time), which is a different clock from the feed and covers only games in the map.
4. The census reads archived rows: it says nothing about live latency now, and the current-day live file grows while it is read (the frozen range excludes it).
5. NOT VERIFIED: basketball wallclock lag (ESPN state has no play id), nba_pbp latency (no shard exists yet; blocked until NBA games are live, S596), wallclock semantics of ESPN core plays vs game clock, any date outside the range.
6. Latency, not a forecast, not a trading claim.

## Builder decisions where the spec left a gap
- wallclock_join null-reason order is no_live_rows, no_wallclock_map, state_has_no_play_key, no_events (E9 needs state_has_no_play_key for basketball even with zero events); a map that covers none of a sport's events also reports no_wallclock_map (its misses are in wc_missing / wc_game_not_fetched).
- poll_gap with live rows but no gap (single-row games only) reports no_events.
- A live row whose request_start_utc does not parse is neither a gap, a prev, nor an event (E5 prev requires a parsable rq; counted in ts_*:request_start_utc).
- The first live row of a game in a file counts game_first_row_in_file only; event_no_baseline counts later rows whose prev PK is None.
- The E9 map used here was fetched once (2 ESPN GETs) and is COMMITTED as docs/evidence/forward/latency/2026-09-22_2026-09-28_espn_wallclock_map.json (sha256 72435fecee36787ff8dcf21ad7fc6a28cf80c912feb35eb00a2166db56a248f4, eol=lf; AMENDMENT 2); the receipt reproduces byte-identically from committed inputs plus the archive.
