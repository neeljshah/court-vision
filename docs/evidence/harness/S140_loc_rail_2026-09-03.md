## Correction applied by the verifier

Two of the three new siblings back-import their parent at the top of the file
(`corpus_cache_sources` -> `corpus_cache`, `screen_predictor_supply` ->
`screen_predictor`), while the parent imports names from the sibling. Importing
the SIBLING first in a fresh interpreter therefore crashed:

```text
scripts.platformkit.combo.corpus_cache_sources
  AttributeError: partially initialized module ... has no attribute '_NBA_PAIR_DIFFS'
scripts.platformkit.foundry.screen_predictor_supply
  ImportError: cannot import name '_families_of' from partially initialized module ...
```

No shipped importer imports a sibling directly, so nothing was broken today, but
`ops/pod_bootstrap_check.py` probes modules by name in a fresh child and any
future direct import would have failed. Fix: the back-import moved to the BOTTOM
of each sibling, after the names the parent needs are defined. Both orders now
import cleanly; all six modules verified as a fresh-interpreter first import.
`results_db_sql` has no back-import and needed no change.
