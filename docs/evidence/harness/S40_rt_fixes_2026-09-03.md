## RT-1 -- `eval_gate/romano_wolf.py`: a degenerate arm NaN-poisoned the family max statistic

Reproduction (scratch `repro_rt1.py`, defaults `n_bootstrap=2000, seed=2718`): one arm of 30
games x 6 states, per-game effect 0.0047 (sd 0.012 between games, 0.002 within), plus a control
arm whose loss differential is identical to the benchmark (constant zeros, so `scale == 0`).

| | before | after |
|---|---|---|
| arm alone | adjusted_p 0.08646, rejected False | adjusted_p 0.08646, rejected False |
| arm + control arm | adjusted_p **0.00050**, rejected **True** | adjusted_p 0.08646, rejected False |
| the control arm itself | adjusted_p 0.00050, rejected False | adjusted_p 1.0, rejected False |

Before, line 68 divided by `scales` unmasked; `RuntimeWarning: invalid value encountered in
divide` fired on every bootstrap draw, `np.max` propagated the NaN, `nan >= observed` was False
for all 2000 draws, and the family's adjusted p collapsed to 1/(B+1) = 0.00050. Adding a control
arm turned a non-significant arm into a FWER-"corrected" rejection.

Fix: mirror `spa_test.py:107` -- `usable = np.isfinite(scales) & (scales > 0.0)`, fill `boot`
with zeros and divide only on `usable` columns; the independent branch hoists its per-row scale
out of the bootstrap loop and `continue`s on an unusable row (which is exactly where the old
`0.0 if scale == 0.0 else ...` short-circuit already skipped its RNG draw, so the bootstrap
stream is unchanged for every non-degenerate family). Masked arms are excluded from `order`, so
they leave both the max statistic and the stepdown, and each keeps adjusted_p 1.0 / rejected
False. For an all-usable family `order` is the same array as before -- the three pre-existing
tests are bit-identical.

## RT-8 -- `combo/planted_null_fdr.py`: a crashed null was scored as a non-ship

Reproduction (`repro_rt8.py`): `run_family_nulls("interaction", n=20, n_games=20, ticks=4,
gate=<always raises>)`.

| | before | after |
|---|---|---|
| 20/20 nulls crash | `fdr_hat=0.0, n_shipped=0, frozen=False` (no error field) | `fdr_hat=None, n_shipped=0, n_error=20, frozen=True` |

Before, the lane reported "the gate is not manufacturing ships" having measured nothing, at
`logger.debug`. Fix: count crashes in a new `n_error` field (additive, defaulted, declared last
so positional construction is unaffected), exclude them from the denominator
(`fdr_hat = n_shipped / (n_run - n_error)`, `None` when nothing was scorable), log at WARNING,
and freeze on `n_shipped > 0 or n_error > 0 or fdr_hat > budget`. `fdr_hat` widens from `float`
to `Optional[float]`, matching the existing in-repo precedent
`improve/segment_planted_nulls.py:73` (`fdr_hat: Optional[float]  # None => INSUFFICIENT`).
The clean paths are unchanged: 0 errors still gives 0/20 = 0.0 and 20 ships still gives 1.0.

## RT-11 -- `eval_gate/shin.py`: price guards were bare asserts

Reproduction (`repro_rt11.py`, run twice -- plain and `python -O`):

| input | before (plain) | before (`-O`) | after (both) |
|---|---|---|---|
| `shin_devig([1.1111, 0.4762])` | p=[0.81745, 0.18255] z=0.734047 sum=1.000000, no error | same | `ValueError: implied probs must be finite and in (0, 1]` |
| `shin_devig_decimal([0.9, 2.1])` | AssertionError | p=[0.81746, 0.18254] z=0.734065, no error | `ValueError: decimal odds must be finite and > 1` |

Fix: all three `assert`s become explicit `raise ValueError` (they survive `python -O`), and the
bisection carries a `converged` flag -- an unconverged solve whose residual exceeds 1e-9 raises
instead of being rescued by the `p = p / p.sum()` line, which stays what it was documented to be
(a rounding clean-up; the measured residual on every real book is ~1e-13).

CORRECTION to the memo's stated mechanism, measured not assumed: the red team attributed the
`[1.1111, 0.4762]` output to a bisection that "cannot bracket a root". It does bracket -- an
instrumented replay of the identical loop converges at iteration 36 with |sum-1| = 9.4e-14. The
wrong number came from an entirely unguarded input: an implied probability of 1.1111 is not a
probability, and only `pi > 0` was checked. The root fix is therefore the domain guard
`0 < pi <= 1`; the non-convergence raise is the additional hardening the memo asked for and is
NOT the path that produced the measured output.

## RT-19 -- `clv_ledger_io.py`: the ledger lock failed OPEN under contention

Reproduction (`repro_rt19.py`, this box, `_LOCK_KIND = "msvcrt"`, a real backend): hold the lock
on one handle, then contend it.

| | before | after |
|---|---|---|
| contended `_acquire` | returns False after 5.02s | returns False after 5.20s (unchanged by design) |
| `with ledger_lock(target):` | **body ran unlocked** after 5.01s | raises `LedgerLockError`, body never runs |

Two concurrent charges could both read `prior=K` and both write `K+1` -- a lost update that
UNDERCOUNTS K and loosens `eps_eff`, the exact failure `_charge_ledger`'s own comment claims to
prevent. Fix, all inside the one shared primitive so every read-max+append critical section is
covered at once (`backtest_runner:143`, `combo_search:107`, `gate_run_carryover:146`,
`interaction_factory/runner:510` and the four `replicate_*` sites, none of which needed editing):
`_acquire` now backs off (20ms doubling to a 250ms cap; the 5.0s deadline is NOT moved), and
`ledger_lock(path, *, required=True)` raises `LedgerLockError` when a real backend exists and the
lock was not taken. The happy path is byte-identical. `required=False` preserves the documented
never-raise contract for this module's own `append_row` / `append_row_if_new` -- important
because `append_row_if_new` swallows exceptions and would otherwise silently DROP a settlement
row instead of writing it. With no lock backend at all (`_LOCK_KIND == "none"`) the block still
runs: there is nothing to fail closed against on such a platform.

Checked before defaulting `required=True`: no `ledger_lock` block anywhere in the repo nests
another `ledger_lock` on the same path (`io_atomic.append_jsonl_atomic` does not lock;
`autoloop/replication_job` and `autoloop/false_discovery_job` both explicitly avoid a second
wrap), so nothing self-deadlocks into the new raise.
