## CHANGE (owned files: scripts/platformkit/ingame/capture_scheduler.py, local_capture_runner.py,
## served_concurrency.py, NEW scripts/platformkit/ingame/capture_repoll.py (helper; the first two files are at
## the 300-line cap), NEW tests/platformkit/ingame/test_s767_repoll.py, this spec, S767_result_2026-10-05.md;
## plus any existing test file whose exact request list or share arithmetic must change, listed in the memo)
1. For every scheduled game inside its focus window (start - 120 s .. start + 3600 s) the planner emits one extra
   book request ("focus_repoll") for the schedule row's SELECTED ticker, executed no earlier than
   tick start + focus_tick_s / 2 (the runner waits for that instant before acquiring the limiter).
2. Trades for scheduled tickers are planned every second tick (alternate by tick parity); S733's 120 s
   query overlap keeps closure complete. Unscheduled focus and live-focus games use only leftover budget.
3. The tick runs on a fixed grid: the next tick starts at previous start + focus_tick_s (never later because
   the tick's own work ran long; carried work is carried as today).
4. Budget arithmetic at 3 req/s (15 per tick): per scheduled two-outcome game 2 books + 1 repoll + 1 trade on
   average = 4; one / two / three games = 4 / 8 / 12, leaving 11 / 7 / 3 for bulk, discovery and reserve.
   served_concurrency's capacity must derive from the same per-game cost function the planner uses (one source,
   imported, and a test that fails if the two disagree); if three games cannot fit, the capacity says so.
5. No change to forward_capture_profile.json, freshness ages, TTLs, qualification bars, seal-pinned files
   (S515 memo: local_capture_writer.py, capture_watchdog.py), or the limiter's rate ceiling.
