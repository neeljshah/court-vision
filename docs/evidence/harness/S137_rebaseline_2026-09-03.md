## 6. ONE LATENT DEFECT FOUND WHILE DOING THIS (not fixed here -- register row proposed)

`pd.read_csv(..., comment="#")` is used to read the archived series in
`eval_gate/s106_requote.py:88`, `eval_gate/s121_requote.py`, and
`eval_gate/tick_informative.py:requote`. **The S116 archive keys its clusters as
`mlb:KXMLBGAME-26JUL051230NYMATL#1`.** Read with `comment="#"`, pandas truncates every row at
the `#`, and the loss column comes back **all-NaN on 9,669 of 9,669 MLB rows** -- which is how
this lane first hit `ValueError: no non-null game/loss rows` rather than a wrong number. On the
archives those three modules actually read (`s82_..._series`, `s58_trialA_..._series`) there is
no `#` in any cell, so **no landed number is affected today**; but the failure mode is silent
truncation, not an exception, and the in-game cluster convention now routinely contains `#`.
`s137_rebaseline.archive_quote` reads without `comment` and says why in a comment at the call.
The three landed modules are NOT edited by this lane (they are landed modules and this lane owns
none of them); the register row text is in section 8.
