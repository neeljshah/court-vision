## Disclosures

- Recurrence churn: an off-day PASS can flip to FAIL at a later scan the same evening if a later D1 run refuses
  otherwise; latest row wins with no fallback to an earlier clean row, so one fetch blip on the last D-1 run leaves a
  P1 for D, cleared per A5(ii).
- A torn line voids the proof. The tick repairs a torn tail only on the next append to the same file, so a tear on the
  last append of UTC day D-1 stays in a closed file. Clear: (i) the owner moves the torn tail out exactly as the tick's
  repair would (next scan re-evaluates; a PASS closes the issue), or (ii) a hand-written <D>_run.json. The
  .partial.json is not read.
- A low-RAM-deferred schedule row, and a schedule-step exception raised before paper_desk_actions.py:91, carry
  subject = UTC date, not D, so they neither prove nor void D; the exception row is flagged by tick_refused.
- A census stdout line over 2048 bytes is truncated by the tail bound (paper_desk_process.py:73,81): no proof.
- An off-day PASS relies only on the ESPN/MLB listing having no pre-game game for UTC D, as reported by schedule_d1's
  census; nothing else confirms the listing.
- The tick still reruns D1 on every tick of an off day (other lead). A hand-written <D>_run.json still passes
  unconditionally (S510 A4 unchanged).
- If the tick-side rerun fix journals a suppressed rerun under a new decision/reason, this accept-set does not match it.
