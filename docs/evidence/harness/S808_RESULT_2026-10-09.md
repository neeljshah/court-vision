## Cause (fresh reads of the 10-08 tennis state shard, served games only)
1. ORIENTATION. The state's `home_abbr` / `away_abbr` are full player names (e.g. "DALIBOR SVRCINA" / "CAMERON NORRIE"), while the ticker suffix is a 3-letter code (`KXATPMATCH-26OCT08NORSVR-NOR` gives "NOR").
   The ticker code is in the aliased {home, away} set for 0 of 11 served games (contract tier checked all 11). So the sealed `_mid` raises
   orientation_unresolved on every eligible tick (1169 of 1169; the other 96 are book_absent).
2. SETTLEMENT. The tennis `state` carries only `players` (14,278 of 14,278 rows: name, sets_won, winner) and no
   `home_score` / `away_score`. The sealed `ticker_outcome` -> `_scores` raises KeyError, giving settlement_refused 14685 and all 11 games unsettled.
3. NO LIVE TICKS. Served tennis statuses in the 10-08 shard were pre 1265 and final 13013, with zero `live`.
   The capture maps STATUS_IN_PROGRESS to live (local_state_capture_sources.py:28), but none was observed. Even with
   orientation fixed, only pre-live ticks would exist, and the sealed POLICY says tennis regulation is
   "unavailable: no scheduled regulation clock".
