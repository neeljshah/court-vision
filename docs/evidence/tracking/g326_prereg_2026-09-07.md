## 2. Enumeration command (the sweep denominator)

    grep -rn "sha256\|hashlib" scripts/platformkit --include=*.py | grep -v "_test"

narrowed to the FILE-READING subset by requiring the same source line to match BOTH
`read_bytes()\|open(...,"rb")\|stream.read(` AND `hashlib.(sha256|md5|sha1)|digest.update|sha256(`.
Committed hash constants are enumerated separately by
`grep -rnoE "[\"'][0-9a-f]{64}[\"']" scripts/platformkit --include=*.py` and by reading each
comparison site found by `grep -rn "assert\|!=\| == " scripts/platformkit --include=*.py`
filtered to lines naming a digest. The union is the denominator. This is a CONSTRUCT: the
enumeration is exhaustive over `scripts/platformkit/**`, not a sample (Q7; A3 does not apply).

## 3. Classification rule (exactly one class per site, fixed before looking)

  DEFECT            hashes a text artifact (.md .csv .json .txt .py) from raw file bytes AND the
                    digest is compared against a value committed to the repo (a 64-hex literal, a
                    committed sidecar, or a field inside a committed evidence artifact).
  RECORD-ONLY       hashes a text artifact but only writes the digest into an output; no committed
                    comparison, so no re-execution can fail. Counted, NOT converted.
  BINARY            the hashed path is .mp4 .png .pt .parquet .npy .gz. Fine.
  IN-MEMORY/SAME-RUN the hashed bytes never come from a checked-out text file (git blob, json.dumps,
                    str.encode, an in-run prefix split), or both sides are computed in the same run.
  ALREADY-LF        the site already strips b"\r\n" before hashing. Fine.

## 4. The helper's exact normalization

`scripts/platformkit/hash_lf.py`, one function:

    def sha256_lf(path): return hashlib.sha256(path.read_bytes().replace(b"\r\n", b"\n")).hexdigest()

Byte-level, not text-level: no decode, no encoding assumption, no lone-CR handling, idempotent on
LF bytes. A prior `sha256_lf` exists at `scripts/platformkit/tracking/g305_additive_registration_verdict.py:41`
but it decodes as UTF-8 and is private to that G305 record; the shared helper is byte-level so it
works on any encoding. Sites already using an inline `.replace(b"\r\n", b"\n")` are NOT rewritten.

## 5. Hash-delta rule (the gate on every conversion)

For each DEFECT site, recompute BOTH digests of the sealed path on this checkout:

    raw = sha256(p.read_bytes())          lf = sha256(p.read_bytes().replace(b"\r\n", b"\n"))

  committed == lf   -> the seal was taken on LF bytes. CONVERT the site. 0 committed hashes change.
  committed == raw  -> the seal was taken on CRLF bytes on the authoring machine and can never be
                       reproduced on an LF checkout. DO NOT CONVERT that site. Report it as a
                       FINDING naming the owning row and the file:line.
  committed == neither -> report as a separate FINDING; convert nothing.

NEVER edit a committed hash constant, a committed evidence artifact, or a threshold to make an
assertion pass. A site whose committed seal is CRLF-derived stays un-re-executable on an LF
checkout and the memo says so in those words.

## 6. Test design

`tests/platformkit/test_g326_crlf_safe_hashes.py`, per-file, no network, no fixtures beyond tmp_path:
  T1 write identical content to two tmp files, one with b"\r\n" and one with b"\n"; assert
     sha256_lf is EQUAL on both and that raw sha256 DIFFERS (the defect, demonstrated).
  T2 assert sha256_lf is idempotent: sha256_lf(lf_file) == sha256(lf_bytes).
  T3 regression on the converted site: assert the committed seal it asserts is reproduced by
     sha256_lf on this checkout, and record whether raw sha256 reproduces it.
  T4 import and execute the converted module's seal check on this checkout and assert it no
     longer raises.
Every touched module's existing test file is re-run INDIVIDUALLY. Never a full pytest.

## 7. Verdict rule

DONE if every DEFECT site is converted with a passing test and 0 committed hashes change.
PARTIAL, with the explicit unconverted list and its hash-delta evidence, otherwise.
