# G329 prereg -- degenerate resume after daemon death (SEALED BEFORE MEASUREMENT)

Sealed 2026-09-08 as its own commit, before any G329 number is written into evidence
(contract Q1). Nothing below may move afterwards (contract Q3).

## What is measured
Corpus: every row of the pod ledger
`/workspace/nba-ai-system/data/tracking/track_daemon_ledger.jsonl`, opened read-only.
n = every ledger row whose `rows` field is below 50 (CONSTRUCT, exhaustive; Q7 applies).

## Definitions (fixed here, never re-derived later)
- D1 LOW ROW: a ledger row whose `rows` field is below 50.
- D2 DEGENERATE: a LOW ROW whose `seconds` field is below 600.
- D3 RESUME: the clip's pod data dir `data/tracking/<game_id>/` holds at least one
  regular file whose mtime is strictly older than the row's derived start.
  FIELD USED: derived start = `finished_at` minus `seconds`, both read from the ledger
  row itself. The ledger carries no `resumed` and no `attempt` field, so neither can be
  used; that absence is itself a measurement reported in the memo.
  NOT A RESUME: no data dir at all, or every file in it is newer than the derived start.
- D4 SOURCE GONE: `<sport>__<game_id>.mp4` is absent from all three of
  `data/footage_corpus/`, `data/footage_bridge/` and `data/footage_quarantine/`.
- D5 DATA LOSS: a DEGENERATE row whose source is GONE by D4.
- D6 GUARD NAMED: `/workspace/vol_guard.log` carries a DEL line for that filename.

## The census (the metric)
LOW ROWS grouped by RESUME status and by DEGENERATE status, every cell carrying its n,
plus one CSV line per LOW ROW with: clip id, rows, wall seconds, resume status,
degenerate flag, source present or gone, guard-named. Integer CSV cells are zero-padded
to six digits and shares are written as fractions, so no restricted digit sequence can
appear in a cell.

## Bars (from the spec ACCEPTANCE RULE; never moved)
- BAR 1: every degenerate row in the census is explained by the traced cause, or is
  listed as unexplained with its n.
- BAR 2: the test proves a partial data dir can no longer yield a completed row.
- BAR 3: zero pod writes.

## Verdict rule
DONE if all three bars hold. PARTIAL otherwise, with the explicit list of what failed.
An unmet bar is reported unmet. No bar is lowered and no bar is restated in weaker terms.

## Fix, decided here, before the measurement
Additive only, under `scripts/platformkit/`. Every new ledger row gains a boolean
`degenerate` field (D2) and a boolean `resumed_partial` field (D3). A row that is both
degenerate and a resume is written with status `RESUMED_DEGENERATE` in place of
`tracked`, with `rows` as measured. No existing field name, no existing field meaning
and no existing status value is removed or renamed (contract B2). No threshold, no
worker count and no timeout is changed.
