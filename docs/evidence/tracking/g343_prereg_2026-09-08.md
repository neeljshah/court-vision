## Window rule

The finisher must build `g343_evidence_attack_test_2026-09-08/windows.csv` before
any arm is applied. Eligibility is a clip with both
`data/tracking/<game_id>/tracking_data.csv` and `ball_tracking.csv`, plus the two
committed WNBA tables supplied to the runner as explicit paths. Sort eligible rows
by ASCII `game_id`; take indices `000000, 000015, ..., 000345` (k = 15) and retain
the first 24 eligible rows. The source manifest records game id, league label,
tracking and ball paths, byte sizes, inferred source width and height, and SHA-256
of each complete source CSV. It is frozen before any corruption. The selected row
must use frames 600 through 659 inclusive; if its last source frame is below 659,
use its last 60 frame numbers and record `last_60` in `window_rule`.

`windows.csv` is a preregistered input manifest, not a result. It has one row per
window and is written by the finisher only after all source digests are available.
No arm or harness result may be written before that file exists with 24 rows.

## Arms in native image pixels

A0 copies both window tables unchanged. A1 changes only tracking coordinate columns:
each identity holds its first-window coordinate. A2 changes only the identity column:
the two most-populated identities on one same-team group merge to the first identity.
A3 changes only the ball-table `frame` column by plus 30. A4 changes only tracking
coordinates: scale x and y by 0.9 about the declared frame centre, then add 0.05 of
the declared frame width to both axes. A5 changes only tracking x: `x = width - x`.
The current mirror is image pixels; no court transform is asserted. Rows, columns,
and all non-target values remain unchanged for every arm.

## Result convention and limitations

The power table is descriptive: rejection share is REJECT / applicable windows;
A0 acceptance share is PASS / applicable windows. No baseline-versus-candidate loss
delta is computed. If a delta is later added, improvement means baseline loss minus
candidate loss; positive means the candidate is better. Every corruption with
any-gate rejection below 0.50 receives one named missing-gate candidate.

Image-pixel corruptions cannot express court shrink or mirror ambiguity as geometry
without validated calibration. Twenty-four windows are a screening sample. Rejection
does not establish detection of real errors, and acceptance does not establish
semantic correctness.
