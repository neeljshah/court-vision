- schema s519_prereg_v1; row S519; sport mlb; source_schema live_shadow_v1 (arm rows only).
- population: served MLB games from the recorder's schedule files (<day>_maker_forward.json, live_shadow_io.load_schedules); a game is eligible when the UTC date of its scheduled_start is >= first_eligible_date; earlier games refused game_before_eligible (counted).

Baseline mid; contrast = blend minus mid. Arm A of the scoreboard is named "venue mid"; the word devigged is not used.
- tick: one (game_key, run_nonce, t_epoch) with both arm rows; paired only when both probabilities are finite and strictly inside (0, 1); otherwise counted by reason (blend: the row's own no_quote reason, e.g. p0_missing / state_not_live; mid: mid_unresolved).
- outcome y: ingame_scoreboard_rules.ticker_outcome on the game's last final state row; no final row -> outcome_unsettled (game excluded, counted).
- counting: EVERY arm row is counted by (arm, decision, reason) independently of fills, before pairing; fills and markouts are out of scope (S516).
- dedupe: key (game_key, arm, run_nonce, t_epoch); an identical repeat counted duplicate_row; a differing repeat refuses the whole read (exit 2, no output). A game recorded by more than one run_nonce keeps the run whose first row for that game is earliest; the others are excluded duplicate_run (counted).
- weighting: each game one unit: per game, the mean Brier (and log-loss) per arm over its paired ticks; per-game difference = blend minus mid. Tick counts per game are reported, not used as weights.
- estimator: exec_policy_stats.boot over per-game differences (5,000 draws, seed 7, 90 pct interval draws [250] and [4749], p_ahead / p_behind as in PREREG_S551).
- primary metric Brier; log-loss is secondary and descriptive.
- floors: >= 30 paired games AND >= 5 distinct UTC game dates.
- verdict word: ingame_scoreboard_rules.contrast_verdict(n_games, ci90 lo, ci90 hi, contrast=True) with n_corpora 1, so the word is INSUFFICIENT, UNDERPOWERED or SINGLE-WINDOW, never AHEAD / BEHIND; the sign and interval are reported as numbers.
- stopping rule: exactly one confirmatory look = the first cumulative read (as of a UTC date) at which both floors hold; every later read is DESCRIPTIVE.
- first_eligible_date_rule: UTC date of the seal commit's committer instant + 1 day.
- output shape (for the reader after S503): per-tick paired rows with keys [sport, game_key, ts, y, target ('outcome'), segment (None), losses {mid: {brier, logloss}, venue_prior_state_blend: {brier, logloss}}, contrast] = S503 paired_losses key shape, decimal strings; plus per-game means.
- disclosures: calibration only; one corpus; mid-anchored blend (the blend's p0 is a frozen venue pregame mid); recorder uptime gaps drop ticks, not games; games are assumed independent clusters.
