EACH TICK, in this order, each step independent (one step's failure is journaled and never blocks later steps):
1. LOCK: a tick-level exclusive lock (data/cache/paper_desk/tick.lock, stale after 2 h with the holder pid checked); a second concurrent tick exits 0 with journal event "tick_already_running".
2. CAPTURES: for each configured capture name, a supervisor process present? (psutil command-line match on `capture_supervisor` + `--name <name>`; match the CHILD path only, never a pattern that matches the tick's own command line). If absent -> run the configured relaunch .ps1 hidden, at most once per capture per 60 min (backoff state in data/cache/paper_desk/relaunch_state.json); never kill any process. Record heartbeat ages via capture_watchdog's read-only checks.
3. D1 SCHEDULE: if local time >= 07:00 and docs/evidence/forward/schedules/<tomorrow-local>_maker_forward.json is absent -> run schedule_d1 with the configured --sports, --local-date-tz, books/state roots, --write-pointer. Never --rewrite an existing day.
4. PAPER NIGHTS: for D from (today_utc - backfill_days) to (today_utc - 1), oldest first, if UTC now >= D+1 06:05Z and docs/evidence/forward/nights/<D>.json is absent and docs/evidence/forward/nights/RUNNER.lock is not held -> run `paper_night --date D --as-of <D+1>T06:00:00Z`; at most ONE night per tick; a night whose served schedule file is absent is journaled "night_skipped_no_schedule" and not retried more than once per day.
5. CENSUS: for a night whose record exists and whose census output is absent -> run night_coverage_census --from D --to D with the landed defaults.
6. RAM: before steps 3-5, if psutil available RAM < config min -> journal "deferred_low_ram" and skip (retry next tick).
7. JOURNAL: every step appends one JSON line (UTC ts, step, decision, reason, argv, exit code, duration, produced paths with LF-normalised sha256, free RAM before/after) to data/cache/paper_desk/journal/<UTC date>.jsonl; the tick rewrites data/cache/paper_desk/status.json atomically (os.replace) with the last result per step. The tick never runs git, never edits code or config, never writes data/registry/.

CONTRACT CASES (construct, tmp roots, no network, subprocess/psutil injected): C1 lock contention and stale-lock recovery; C2 capture present -> no relaunch; absent -> exactly one relaunch; second tick inside 60 min -> no relaunch; the match never selects the tick's own process; C3 D1 before 07:00 local skipped, after -> runs once, existing day never rewritten; C4 night due/not-due boundaries at exactly 06:05Z, backfill order oldest first, one per tick, RUNNER.lock held -> skip; C5 census only after a night record; C6 low RAM defers 3-5; C7 one step raising leaves the others running and journals the exception; C8 journal line schema + status.json atomic write; C9 config validation (bad sports, bad tz, missing relaunch script -> refuse that step, journal); C10 install .ps1 dry mode prints a definition with pythonw + hidden_launch, no console, run-only-when-logged-on; C11 a producer -> file -> fresh-process consumer case through the real paper_night.main on a construct root. Pin shas, never master/HEAD; <= 300 LOC per file; ASCII.

LANDING GATE (orchestrator): one real tick run in the main checkout with --dry-run (decides and journals, runs nothing) whose journal shows the right due steps for the current clock; then one real tick; then install the Windows task and observe two scheduled ticks in the journal.
