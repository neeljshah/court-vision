1. `enrich(items, get, league, on_error=None, *, fetch=None, clock=None) -> items` mutates each item's `state` in place and returns the same list. The whole call is wrapped: any exception leaves the items exactly as normalised (counted `play_clock_enrich_error`) and never raises. Untouched rows keep today's keys byte-for-byte (schema additive). It never reads or writes `get.last_receipt` and never calls `get` (StateClient.get retries 403/429 up to 5 times with Retry-After backoff, local_state_capture_io.py:51-82; a play GET must not inherit that). `fetch(url, timeout_s) -> (status|None, body bytes|None, error str|None)` defaults to one `requests.get(url, headers={"User-Agent": "Mozilla/5.0"}, timeout=timeout_s)`, no retry; tests inject it.
2. WHEN: item status == "live" and `state` a dict: pid = state.get("last_play_id"), valid only if a non-empty str or an int (bool refused) whose str() is all ASCII digits; otherwise write last_play_ts None, last_play_ts_source None, last_play_ts_reason "no_play_id" with no request. Event id = str(item["_start"]["id"]) else competitions[0]["id"], digits only, else reason "no_event_id". Non-live items (pre/final/delayed/postponed) NEVER fetch; they get the three keys only when (game, pid) is already cached, otherwise `state` is untouched.
3. CACHE: process-local dict keyed (league, event_id) -> ordered {pid: {ts, attempts, reason}}. A success is final and never refetched. A null result is retried on a LATER tick, 3 attempts total (a 404 just after a new lastPlay is expected), then frozen with its last reason and counted once as `play_clock_gave_up`. Per-game cap 32 pids (oldest evicted), global cap 128 games (oldest evicted); a game's entries are dropped when its item status is "final" (after that row is enriched). A pid different from the previous row's is a miss; an id seen earlier (A, B, A) is a HIT. A restart refetches the current pid once per live game.
4. BOUNDS: per `enrich` call at most MAX_REQUESTS = 12 requests and TOTAL_BUDGET_S = 4.0 s monotonic (injected clock); per-request timeout = min(2.0, remaining budget); the first item over a bound, in item order, gets reason `tick_cap` / `tick_budget` with NO attempt consumed and is retried next tick. Sequential, no threads. Constants are module-level and marked NOT PROFILED in the memo.
5. PARSE (each refusal writes last_play_ts None + its reason and consumes an attempt): 404 -> `http_404`; other non-200 -> `http_error`; fetch error text -> `timeout` (timeout exceptions) or `connect_error`; body not UTF-8 JSON dict -> `json_error`; `id` != str(pid) -> `id_mismatch`; wallclock absent/None/non-str/not fullmatch `\d{4}-\d\d-\d\dT\d\d:\d\d:\d\dZ`/not a real calendar instant (month 13) -> `wallclock_invalid`; wallclock later than the item's `receipt.response_end_utc` + 5 s (equal to +5.000 s is ACCEPTED, +5.001 s refused; unparseable response_end -> no future check) -> `wallclock_future`. Accepted: state.last_play_ts = the wallclock string verbatim, state.last_play_ts_source = "espn_core_play_wallclock", state.last_play_ts_reason = None.
6. COUNTED: every non-success reason increments the existing per-source counter via `report(get, source, "play_clock_<reason>", on_error=None)` (source "nfl"/"ncaaf"; local_state_capture_io.py:183); successes and cache hits live in module counters returned by `counters()`. A play-clock failure NEVER becomes an adapter error, never changes status / source_ts / game_key / raw, never drops the row.
7. Emission: the fields ride `state`, so `_build_row` persists them unchanged and `state_changed` flips only when the id or the ts changes (a null -> ts resolution on retry flips it once; documented in the memo).
