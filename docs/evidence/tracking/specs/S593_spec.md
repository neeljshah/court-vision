SOCKET: one connection per wanted gamePk via `websockets.connect(url, origin="https://www.mlb.com", ssl=<context built from REQUESTS_CA_BUNDLE or SSL_CERT_FILE, else default>, ping_interval=20, open_timeout=15, max_size=1<<20)`. Subscribe = open; unsubscribe = close code 1000 when the game leaves `wanted`. Lifecycle is a dict gamePk -> asyncio task; a task that dies is respawned with the S442 backoff (1,2,4..300 s, reset after >= 600 s connected) only while the game is still wanted; at most `--max-games` (default 16) concurrent, excess counted `games_over_cap` never silently dropped.
3. ROW (one JSONL line per message, fsync after each append, opened append-only; path `<output-root>/push/mlb/<UTC date of receipt>.jsonl`, default output-root data/cache/ingame_state_local_v2): {record_type "mlb_push", schema 1, gamePk (int from the URL, authoritative), receipt_utc (ISO Z microseconds, from ONE wall anchor plus time.monotonic_ns elapsed, so a wall step never reorders rows), receipt_mono_ns, source_ts_utc (parsed timeStamp as UTC ISO Z, or null), source_ts_status "ok" | "missing" | "malformed", lag_s (receipt_utc - source_ts_utc in seconds, 3 decimals, null when the stamp is not ok), raw (the message text EXACTLY as received, a string, never re-serialised), body_sha256}. A message that is not valid UTF-8 / JSON object is STILL written with source_ts_status "malformed" and its raw text (lossless) and counted `frames_malformed`; a binary frame is written base64 in raw_b64 with raw null. timeStamp is treated as UTC (the measured 7.0-7.8 s receipt lag confirms it; a stamp more than 5 s in the FUTURE of receipt sets source_ts_status "ok" but flag `future_stamp` true and is counted, never dropped). A gamePk in the body that differs from the URL's is written, flagged `pk_mismatch` true. Out-of-order timeStamp is written as received (no reorder, no dedup: identical updateId repeats are written and flagged `dup_update_id`). Date rollover: the file is chosen per row from its own receipt_utc.
4. CONTINUITY: on any disconnect write `{record_type "missing_interval_push", gamePk, last_good_receipt_utc (null if none), response_end_ts (disconnect instant), reason}` immediately, and on the next successful open write `{record_type "reconnect_push", gamePk, resumed_utc, gap_s}`. The socket has no replay: the row states the gap, never fills it.
5. HEARTBEAT: every 30 s one row to `<output-root>/push/mlb/heartbeat.jsonl` (rotated by UTC date suffix, same fsync rule): {record_type "heartbeat_push", ts, pid, rss_mb, wanted, connected, frames_total, frames_malformed, reconnects, games_over_cap, schedule_age_s, schedule_stale}; a stdout single-line JSON mirror (ASCII) so capture_supervisor's log shows liveness.
6. HARD RSS CAP + LOCK: `--rss-cap-mb` (default 120): sampled every 5 s with psutil.Process().memory_info().rss; on breach flush, write `{record_type "rss_exit", rss_mb}` and exit code 75 (the supervisor's backoff relaunches). No unbounded queue: frames are written inline (no buffering); per-game `max_size` 1 MiB. Single instance: exclusive create of `<output-root>/push/mlb/_lock.json` {pid, create_time}; a stale lock (pid dead OR create_time mismatch via psutil) is taken over and counted `lock_takeover`; a live foreign lock exits 73 with no writes. Lock removed on clean exit and on STOP.
