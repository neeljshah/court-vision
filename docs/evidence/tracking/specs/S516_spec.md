TIME BASE: origin = 00:00:00Z of --date D; every instant is an exact integer nanosecond after origin (forward_replay_io.stamp, Decimal, never float); a value with a sub-nanosecond remainder or a wrong type refuses the row (`time_not_exact`); latencies, horizons and max_wait are passed to the landed callers multiplied by 10**9, the fill_realism.py convention (NS).  1. INPUT ROWS (streamed, parse_float=str, newline-terminated records only: an unterminated tail is dropped and counted `unterminated_tail`, quarantine files never read; schema must be 'live_shadow_v1' else `bad_schema`): kind 'run' and kind 'arm' matter, kind 'p0' is ignored and counted. An arm row needs arm in {mid, venue_prior_state_blend} (any other arm string: `unknown_arm`, excluded), str game_key/ticker/row_id/run_nonce, decision quote|no_quote, t_epoch (str, exact Decimal) and t_iso agreeing to <= 1 microsecond (else `clock_conflict`), str emitted_ts. Duplicate row_id: the later row is dropped (`duplicate_row_id`). A ticker differing from the (game_key, arm) group's first ticker: `ticker_conflict`, dropped. t_epoch smaller than the previous row's for the same (game_key, arm): dropped, `t_regression`. Every drop is counted in the receipt's refusals block by its own name; a shard line that is not a JSON object counts `bad_line`; nothing raises on row content.
 2. SUBMIT INSTANT (astra 14: do not backdate): the decision instant is t_epoch (the last instant whose information was used). emitted_ts (wall clock after the decision was computed) is not a decision time. Rule: e = emitted_ts - t_epoch; e < 0 refuses the row (`emitted_before_decision`; e == 0 allowed); 0 <= e <= 60 s: submit_ts = emitted_ts (live recorder, compute delay is real); e > 60 s: submit_ts = t_epoch and `replay_stamped_rows` += 1 (a replay run stamps the replay host's wall clock, days later; the count is reported and must be 0 for a live night). Arrival = submit_ts + S, applied by the simulator's own submit_latency_s so it is never added twice. Example: t=23:59:40.000000, emitted 23:59:40.120000 -> submit 23:59:40.120000, arrival 23:59:42.120000; emitted 00:04:41 (61 s) -> submit 23:59:40, arrival 23:59:42, replay_stamped_rows 1; emitted 23:59:40.000000 -> arrival 23:59:42.

INTERVALS per (game_key, arm, side): a QUOTE row carries side ids `yes_bid_quote_id` (price yes_bid_cents) and `no_bid_quote_id` (price no_bid_cents); a side is usable only if its id is a non-empty str, its price is an int (not bool, not float) in 1..99, ids are not reused anywhere in the input (`quote_id_reuse`, the later dropped), yes_bid_cents == bid_cents and no_bid_cents == 100 - ask_cents (else that side `side_map_inconsistent`). End instant = the EARLIEST of: (a) t_epoch of the next kept row for the same (game_key, arm) whatever its decision (a no_quote, final or quote row all cancel; an equal t ends at the same instant); (b) expires_at_epoch (exact Decimal; missing or unparseable -> the row's sides are dropped, `expires_missing`); (c) the t_epoch of the first arm row of a LATER run_nonce in file order (a restart boundary; the run row itself carries no decision instant and is not used as a time); (d) nothing else -- a crash or skip is bounded by (b). No next row and no expiry beyond the shard is impossible by (b). The simulator gets cancel_ts = end instant and cancel_latency_s = C: live = (submit + S, end + C), both ends exclusive as the simulator has it. end + C <= submit + S is a ZERO-LIFE interval: counted (`zero_life_intervals`), never simulated. A next row that carries only one usable side ends the other side. Each row is its own order; the receipt states that queue priority across an unchanged re-quote is NOT modelled. quote_seconds = sum of (end + C - submit - S) over non-zero intervals, exact Decimal. Example: quote row t=00:00:40, expires 00:01:10, next row (no_quote) t=00:01:10 -> end 00:01:10, live 00:00:42..00:01:11 = 29 s per side.
