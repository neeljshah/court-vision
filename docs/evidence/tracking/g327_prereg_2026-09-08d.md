## The sealed RULES

- **BIT-IDENTITY**: equal box count AND, under the arm's own ordering rule, every
  `x1,y1,x2,y2,score` and class equal as float64 with NO tolerance. **Two zero-box frames
  ARE bit-identical.** Where full identity including score and class is not what a number
  measures, the number is called **coordinate-exact**, never bit-exact.
- **AGREEMENT**: IoU >= 0.5, one-to-one, greedy by descending IoU, both directions with
  denominators, reported SEPARATELY from bit-identity. The verdict turns on bit-identity.
- **EVERY EVALUATED FRAME IS IN EVERY DENOMINATOR**, zero-box frames included. Each arm
  writes its OWN raw CSV at run time and a zero-box frame is an EXPLICIT row there
  (`n_boxes` `000000`, empty box fields), so no frame is ever restored from a summary.
- **CSV-ONLY RECONSTRUCTION**: bit-identity, count deltas and both-way agreement are
  recomputed from the seven per-arm CSVs ALONE. **No reported value may come from
  `g327a2_summary.json`.** The only other input to scoring is `g327a2_arms.csv`, the run's
  own record of the MEASURED tensor shape and dtype, which decides whether an isolation
  arm's factor was applied and carries no comparison value.
- **Q6 SERIALISATION**: every coordinate and score is written as its EXACT dyadic
  fraction `num/den`, both parts zero-padded to six digits, which round-trips with no
  tolerance; every share is an integer fraction pair, never a bare decimal; every pixel
  delta is an integer thousandth of a pixel; every integer cell is zero-padded to six
  digits. Attempt 1's shortest-round-tripping decimal cells carried restricted digit
  sequences on 12 of their committed rows, and a decimal point cannot be reformatted out
