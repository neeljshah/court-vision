## 1. PREMISE CENSUS -- SCOPE AND DETECTION RULE (step 0, binding before-condition)

SCOPE. An ARTIFACT DIRECTORY is every immediate child directory of `docs/evidence/tracking/` or
`docs/evidence/harness/` that holds at least one git-tracked file at any depth. Every tracked file
below it is in scope, at any depth, head to tail, no sampling and no head slice (contract B7).
Nested sub-directories are not separate rows; their files count toward the immediate-child row that
contains them. Files sitting DIRECTLY in a root are not a directory and are reported as their own
out-of-scope class with their n. The G62 output directory
`docs/evidence/tracking/g62_environment_sidecar_2026-09-08/` is excluded by name, so the census
reports the state BEFORE this row and stays reproducible after the row lands.

READING. A file is decoded as UTF-8 with replacement; a `.gz` file is decompressed first; a file
whose extension is one of `.png .jpg .jpeg .mp4 .pt .npy .npz .parquet .zip .tar .ico .pdf` is
counted as binary and not scanned. Every count is reported with its n.

DETECTION. A directory CARRIES AN ENVIRONMENT RECORD when at least one scanned file matches at
least one of these fixed patterns, applied case-insensitively:
- JSON key class: a `.json` / `.jsonl` file that parses, any key at any depth equal to one of
  `python`, `python_version`, `py_version`, `platform`, `hostname`, `host`, `node`, `nodename`,
  `torch`, `torch_version`, `numpy`, `numpy_version`, `pandas`, `cv2`, `cv2_version`, `opencv`,
  `opencv_version`, `ultralytics`, `scipy`, `sklearn`, `cuda`, `cuda_version`, `cudnn`,
  `omp_num_threads`, `mkl_num_threads`, `torch_num_threads`, `num_threads`, `threads`,
  `thread_count`, `cpu_count`, `environment`, `env`.
- Text class, in any scanned file including prose: `python` within 12 characters of `3.<digits>`;
  `numpy`, `torch`, `ultralytics`, `cv2` or `opencv` each followed within 4 characters of
  separator by `<digits>.<digits>`; the literal `OMP_NUM_THREADS` or `MKL_NUM_THREADS`; `thread`
  or `threads` followed by a separator and digits; the literal `hostname`.
Prose counts. A memo that states the python version IS recording it; this biases the census toward
finding MORE environment records, which is the direction that can only weaken this row's premise.

STOP CONDITION. `has_python_version` and `has_numpy_version` are recorded per directory by the two
named patterns. **If more than half of the artifact directories carry BOTH, the premise is FALSE:
the row stops at the census, the memo is written, the row is committed and reported PREMISE FALSE.**
No sidecar is then hooked anywhere.

The census is produced by `scripts/platformkit/tracking/g62_env_census.py` writing
`census.csv` (columns: root, directory, files_tracked, files_scanned, files_binary,
has_env_record, has_python_version, has_numpy_version, keys_found; integer cells zero-padded to six
digits) so the verifier recomputes the headline fraction from the artifact alone (contract A2).

## 2. THE SIDECAR AND ITS KEY LIST

`scripts/platformkit/env_sidecar.py`, at most 150 lines, ASCII, additive: `capture()` returns the
dict, `write()` serialises it to `environment.json` with `sort_keys=True` so key order is
deterministic, and `read()` returns `None` for a directory that has no sidecar. `capture()` NEVER
raises on a missing library, an unreadable git revision, an unreadable cgroup file or a named module
that does not exist; each such field becomes an explicit null carrying its reason, never a silently
empty string reported as present (spec NON-TAUTOLOGY, following G48).

Keys, fixed here: `schema`; `captured_utc`; `python_version`; `platform`; `host` (`hostname`,
`role`, `role_rule` -- the role is `pod` when `/workspace/nba-ai-system` exists and `local`
otherwise, and the rule string is written into the artifact so the derivation is auditable);
`cpu_count`; `cgroup_cpu_quota` (null when unreadable); `threads` (`OMP_NUM_THREADS`,
`MKL_NUM_THREADS`, `torch_num_threads`); `libraries` (`numpy`, `pandas`, `torch`, `cv2`,
`ultralytics`, `scipy`, `sklearn` -- each the version string or null); `torch_build`
(`cuda_available`, `cuda_version`, `cudnn_version`, all null when torch is absent); `git`
(`head_sha`, `dirty`, `unavailable_reason`); `seed` and `seed_reason`; and `modules`, a list sorted
by path of `{path, sha256, unavailable_reason}`.

No secrets, no tokens, and no environment variable beyond the two named thread settings is read or
written. The seed is null with an explicit reason on every route that seeds nothing.

MODULE HASHES (original spec step 2b, G52 precedent). The whole repo is NOT hashed. Each hook names
the first-party modules whose content determines its artifact, fixed here: `census_recomputable`
names `scripts/platformkit/tracking/census_recomputable.py`; `g330_run_attempt2` names
`scripts/platformkit/tracking/g330_run_attempt2.py`, `.../g330_attempt2.py` and
`.../g330_panorama_identity.py`; `g310_instance_key` names
`scripts/platformkit/tracking/g310_instance_key.py` and `.../g310_native_input_arm.py`. Library
code is excluded because its identity is already carried by the `libraries` versions, and model
weights are excluded because they are data, not modules.

## 3. HOOK LIST, SELECTION RULE AND OPT-OUT

SELECTION RULE, fixed here: among `scripts/platformkit/tracking/*.py` that both reference
`docs/evidence/tracking` and create their output directory, keep those that have an existing
per-file test and at least 40 lines of headroom under the 300-line rail, then take the three most
recently committed. That rule selects, and this row hooks, exactly these three:
- `scripts/platformkit/tracking/census_recomputable.py` (193 lines; `tests/platformkit/test_g319_census_recomputable.py`)
- `scripts/platformkit/tracking/g330_run_attempt2.py` (240 lines; `tests/platformkit/test_g330_panorama_identity.py`)
- `scripts/platformkit/tracking/g310_instance_key.py` (202 lines; `tests/platformkit/test_g310_instance_key.py`)
`scripts/platformkit/tracking/g327_detector_batch_stability.py` (275) and
`.../g331_evaluated_frames_sidecar.py` (291) are excluded by the headroom clause and are named in
the memo as deliberately skipped, with every other candidate.

OPT-OUT: each hooked runner accepts `--no-env-sidecar`, and with it passed the runner's behaviour
and every byte it writes are identical to master. Default ON is acceptable under contract B2
because the sidecar is a NEW file with a new name: no existing key is renamed or removed, no
existing file changes, and every reader of those outputs keeps parsing them unchanged.

`~/bin/pod_run` is outside the repo and is NOT edited; the memo documents the one-line call the
orchestrator may add. `lane_commit.py` does not exist in this repo -- `git ls-files` returns nothing
for it -- and so cannot be hooked; the memo says so.

## 4. CONSTRUCT CASES (original spec: n >= 3 constructed artifacts; contract Q7 enumeration)

Enumerated here, not sampled, in `tests/platformkit/test_g62_environment_sidecar.py`:
1. WITH TORCH -- capture on this box as it is; every schema key present with the declared type.
2. WITHOUT TORCH -- the torch import is monkeypatched to raise; `libraries.torch` and every
   `torch_build` field are null and nothing raises.
3. DIRTY TREE -- the git probe is monkeypatched to report a non-empty status; `git.dirty` is true.
4. UNREADABLE REVISION -- the git probe is monkeypatched to fail; `git.head_sha` is null and
   `git.unavailable_reason` is a non-empty string, never a silent empty sha.
5. MISSING MODULE -- a named module path that does not exist yields `sha256` null with a reason.
6. STAMPLESS ARTIFACT -- a directory with no `environment.json` is still parsed: `read()` returns
   `None` and does not raise, so an old artifact never becomes unreadable.
Cases 1-3 are the three constructed artifacts the original spec requires; 4-6 are the null paths.
