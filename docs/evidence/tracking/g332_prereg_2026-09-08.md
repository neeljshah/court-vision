**B2 -- every landed signature stays callable with its old arguments.** Every new argument
is a keyword with a default. `fatal=True` is the ONE deliberate default CHANGE: a rerun of
G327 that silently scored a reduced frame set is exactly the defect, so the safe default is
to stop. It cannot alter a committed number, because the committed attempt-2 snapshot
verifies whole -- clause 3 below is the executable proof of that -- and `fatal=False` stays
reachable for anyone reproducing the landed drop-and-continue.

**The snapshot-list rule (c1), stated so it can be checked.** A JSON list whose entries are
ALL objects, with at least one entry, is a SNAPSHOT-LIST CANDIDATE. Its LENGTH, and every
count-keyed integer inside its entries, are snapshot-list values. They count as
RECOMPUTABLE only when EVERY entry carries a `sha256`-keyed 64-hex string, a timestamp-keyed
value and a count-keyed integer, and -- when the list holds more than one entry -- each
entry after the first repeats its predecessor's sha256 among its own string values
(CENSUS_RULE.md clause 2, lines 10-14). Otherwise those values are UNVERIFIED, and a count
whose EVERY unmatched component is reproduced only by such values gets `UNVERIFIED_SNAPSHOT`
instead of `RECOMPUTABLE`. A count with a component no artifact reproduces at all stays
`NOT RECOMPUTABLE`. Lists of non-objects are not snapshot lists and keep contributing their
length, since CENSUS_RULE clause 1 puts a committed artifact's own contents out of scope.

**The fallback rule (c2).** `--construct-only` (default OFF) is the ONLY way to reach the
filesystem walk. With it off, a git-index failure RAISES, carrying the git error text.

**The TXT rule (c3).** A `.txt` artifact contributes its non-blank line count ONLY. The
header subtraction is reachable with `--txt-header`. CSV keeps both values, as landed.
