## The rule this row writes, in outline

`docs/evidence/tracking/CENSUS_RULE.md`, at most 40 lines, stating this and nothing more:

1. SCOPE -- every count a memo reports over a MUTABLE source: a ledger, a corpus listing, a job
   root, a log, a live directory. A count over an immutable committed artifact is out of scope.
2. THE OBLIGATION -- such a count must be recomputable either from a committed snapshot of that
   source taken at the time of the count, or, when the bytes are too large to commit (over 5 MB per
   file), from a committed hash-chained snapshot list carrying sha256, row count and timestamp per
   snapshot, with the projection of the columns the count uses committed in place of the bytes.
3. ORDER -- the snapshot is taken AFTER the prereg seal and BEFORE the count, and the count is
   computed from the snapshot, never from the live source.
4. THE FALLBACK -- a count with neither is reported in the memo as NOT RECOMPUTABLE, in those
   words, never silently.
5. REPEATED READS -- when a memo reports a sequence of reads of one source, EACH read needs its own
   snapshot or snapshot-list entry; one snapshot backs one read.
6. WHAT THE RULE IS NOT -- it does not say a count is right, only that it can be recomputed.

The rule is written once, in that file. It is not restated in the register, in the contract or in
any landed memo, and no landed memo is edited to comply with it retroactively.

## The check: parsing scope and verdict vocabulary

`scripts/platformkit/tracking/census_recomputable.py`, at most 200 lines. Given a memo path it does
exactly this, and its limits are declared here in advance rather than discovered later.

WHAT IT PARSES.

- A COUNT is either a slash sequence of two or more integers (`<a>/<b>`, `<a>/<b>/<c>`, and so on)
  or an `n = <k>` form. A slash sequence is ONE count whose COMPONENTS are its integers.
- A slash sequence is rejected when the character on either side is a word character, a dot, a
  colon or another slash. This drops file paths and clock times, and it drops nothing else on
  purpose.
- A count NAMES A SOURCE when its own line carries a source noun (ledger, row, file, frame, clip,
  record, segment, run, game, line, job, entry, snapshot, census, corpus, id, cell, observation,
  detection, memo, artifact, and their plurals). A count whose line carries none is UNPARSED.
- An ARTIFACT the memo names is any token ending `.csv`, `.csv.gz`, `.json`, `.jsonl`, `.tsv`,
  `.txt` or `.gz` that resolves to a file in the repository index (`git ls-files`; a filesystem
  walk only when that index is unavailable, which is the case only under the test). A token with a
  slash resolves by path suffix, a bare basename by basename.

WHAT COUNTS AS REPRODUCING A NUMBER. From each artifact the memo names, the check derives a set of
integers: for a CSV or TSV, the line count and the line count less the header; for a gzipped CSV,
the same two after decompression; for a JSONL, the non-empty line count; for a JSON, the length of
every list plus every integer value whose key carries a count word; for a TXT, the line count. A
count is RECOMPUTABLE when EVERY one of its components appears in the union of those sets.

VERDICT VOCABULARY, exhaustive, exactly these four strings:

- `RECOMPUTABLE` -- every component of the count is reproduced by a committed artifact the memo
  names, and that artifact is named in the output.
- `NOT RECOMPUTABLE` -- the count names a source and at least one component is reproduced by no
  committed artifact the memo names. The missing components are named.
- `UNPARSED` -- the parser found a count-shaped token but its line names no source, so the check
  declines to judge it. The reason is printed.
- `ABSENT` -- the memo itself is not committed on master. No count is claimed for it and its n is
  zero.

## Limits stated in advance

- The parser is heuristic and reads prose. It will miss any count written in words, any count whose
  source noun sits on a neighbouring line, and any count spelled in a shape it does not match. It
  reports what it could not parse; it cannot report what it did not see.
- A `RECOMPUTABLE` verdict means a committed artifact reproduces the integer. It does NOT mean the
  integer is correct, that the artifact is the source the memo actually counted, or that the
  artifact was snapshotted before the count. Coincidence between an integer in a JSON and a count
  in prose is possible and is not excluded.
- The rule cannot retroactively create snapshots for rows that have already landed. Their caveats,
  named per owning row, are the deliverable of this row; applying them to the register is the edit
  of the orchestrator, not of this row.
- Counts are referred to in the memo by LINE NUMBER in their memo rather than transcribed, so that
  no retracted token is reprinted (Q6).
