# G381 preregistration

Scope: preparation only. This preregistration fixes the token grammar, resolution
order, and classification vocabulary before any census is run outside synthetic
fixtures. The first production census is intentionally deferred until this file
is committed alone by the orchestrator.

## Inputs and enumeration

Read master history only. Enumerate additions matching
`docs/evidence/tracking/g*_*.md` and `docs/evidence/tracking/G*_*.md`. A memo is
in scope when it contains a token matching either `\\b[0-9a-fA-F]{64}\\b`, or
`\\b[0-9a-fA-F]{8,63}\\b` on a line containing `sha` case-insensitively.
Record every matched token with its memo path and one-based line number.

## Resolution order

For the backticked path nearest the token on its line (or `NONE`), at the first
master commit adding that memo: (a) compare `git hash-object --no-filters` of
the named artifact at landing; (b) repeat at HEAD; (c) compare SHA-256 of the
landing artifact after CRLF-to-LF normalization; (d) compare the token against
every blob id reachable from the landing tree under the memo same-stem evidence
directory; (e) mark unresolved. A full token requires equality. A prefix
resolves only if exactly one candidate starts with it; zero or two-or-more
candidates do not resolve. A quoted `/c/Users/neelj/nba-track-aNN/...` store
path is rewritten under this worktree root before lookup. A truly absent
repo-relative path prints `ABSENT-IN-WORKTREE <path>` and stops.

## Classes and reason vocabulary

Classes are IDENTIFIES_AT_LANDING, IDENTIFIES_AT_HEAD_ONLY, CRLF_ONLY,
ARTIFACT_UNNAMED, and UNRESOLVED. UNRESOLVED reasons are
`artifact never committed`, `pod-only or absolute path`, `prefix ambiguous`,
and `token is not a digest`. The first matching resolution step wins.

## Outputs and checks

The later measurement writes census.csv, per_row.csv, unresolved.csv,
summary.json, eye.txt, and the proposed convention under this directory. It
does not edit existing memos, the register, or a ledger. This preparation run
uses fixtures only. The test reads this preregistration file, normalizes CRLF
to LF, and hashes every byte above the seal line. No scored comparison occurs.
