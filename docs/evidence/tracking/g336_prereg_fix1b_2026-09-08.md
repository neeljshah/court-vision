AMENDMENT 1 -- WINDOW, SEALED. cap = 540 source frames per section, from the unchanged offset
of 90. The route's measured stride is 3 source-frame ids per emitted frame, so this window
seals >= 180 EVALUATED frames per section -- above the spec's `n >= 60 frames` rail and above
the contract's `>= 30` scored-cell rail. The earlier declared cap-240 window is a strict
subset of it (same offset, same sections, same route), so this window extends that rerun
rather than substituting a different one for it.

AMENDMENT 2 -- A REFUSED SECTION IS NEVER SCORED. `scripts/run_clip.py`'s own production
preflight (`:295,453`, exit 4) and its empty-tracking exit (`:533,543`, exit 3) are NEVER
neutralised, patched or skipped, and `COURTV_NO_OCR` is not set. A section the route refuses
is recorded REFUSED with its exit code in `premise.csv` and in the memo, is excluded from
every table, and counts against the bar's denominator of 4. A section whose named input has
rotated out of the live pod corpus is recorded ABSENT the same way; no substitute footage may
be scored in its place.

AMENDMENT 3 -- IDENTICAL OBSERVATION SETS. Both arms are scored on ONE observation set: the
same detections and the same evaluated frames. The set is the detector observations the
production route assigned to a slot; an observation the route left unassigned is dropped from
BOTH arms, and the dropped count is reported per section. The original preregistration's
baseline covered only assigned observations while the candidate covered every recorded one,
which made the two arms incomparable; this clause removes that asymmetry.
On astra's 2026-09-08 critique that internal track ids be isolated from the 10-slot exporter
first: this harness CANNOT do that on this route. The pod has no `supervision` package, so
`advanced_tracker.py:1524` takes the fallback branch in which `_match_team_bytetrack`
(`:886`) assigns an index into the fixed 10-slot `self.players` pool (`:572`) and no separate
internal identifier is ever formed; the supervision path that does carry distinct track ids
(`:993-1041`) maps them back to the same slots and is not the path that runs here. The
slot-keyed ids are therefore scored as the ONLY available baseline ids, and every baseline
number in this row is a statement about reusable slots, not about isolated tracks.

AMENDMENT 4 -- SIGNATURE, DECIDED BY MEASURED COVERAGE. The route attaches its own OSNet
vector (`deep_emb`) only to the detections its movement filter selects
(`advanced_tracker.py:1507-1516`), so the recorder now stores that vector alongside the HSV
signature for every observation and reports the measured OSNet coverage share per section.
The rule sealed here is per section and all-or-nothing: if EVERY scored observation in a
section carries an OSNet vector, that section's cosine term uses the OSNet vectors; otherwise
it uses the HSV signature, because a mixed 512-dimension / 3-dimension set is not comparable
under one cosine. The chosen signature and the measured coverage share are reported for every
section whichever way the rule falls. No other appearance option is permitted.

AMENDMENT 5 -- PREMISE ARCHIVE AND TIMING. The exact route tracking rows the premise reads
are archived as `premise_rows.csv` under the artifact directory (section, frame, player_id
and the four bbox cells as integer thousandths of a pixel), so the premise table is
recomputable from committed bytes alone. Runtime is reported for both arms with this caveat
stated, not compared: the baseline millisecond figure is the production association including
the appearance computation it performs inside that step, while the candidate figure covers
association only over already-recorded observations. The two are not like-for-like and no
speed conclusion is drawn from their ratio; the bar's `runtime <= 2x` clause is judged only
on that stated basis.
