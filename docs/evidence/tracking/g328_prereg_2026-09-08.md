# G328 PREREGISTRATION -- daemon worker accounting vs adjudication

Written and committed ALONE before any G328 measurement was written into evidence.
Row: GAP G328 | sport all | worktree a6 | spec `docs/evidence/tracking/specs/G328_spec.md` VERSION 2026-09-08.

## 0. Premise (binding before-condition)

DEFINITION. A daemon "active print" is one `tracking <game_id> (<sport>), <N> active` line in a
`/workspace/track_daemon*.log` file on the pod. `N` is the value the daemon itself reports. The premise
is TRUE for a daemon instance when at least one active print in that instance log reports `N` strictly
greater than the `--workers` value that instance was launched with.

n. Every active print in every `/workspace/track_daemon*.log` present on the pod at read time -- no head
slice, no sampling. The per-instance table reports ticks-over, ticks-total and the workers value.

WORKERS PROVENANCE. The `--workers` value is taken from `ps -o args` for a live instance. It is NOT
recorded inside the log file by the daemon, and the pod keeps no shell history for the ssh launches, so
for an instance that has already exited the workers value may be UNVERIFIABLE. An instance whose workers
value cannot be read from a live process is reported with its active-print distribution but is marked
workers-unverified and does NOT adjudicate the premise. The premise is adjudicated only on instances
whose workers value is verified.

IF FALSE. If no instance with a verified workers value ever reports an active print above that value, the
premise is FALSE: stop, write the memo, commit, report PREMISE FALSE. No cap is built in that case.

## 2. Method -- adjudication timing and concurrency

Two candidate sources are named in advance, and which one is usable is a finding, not a choice made after
seeing the answer:

  (a) LEDGER FIELDS. `data/tracking/track_daemon_ledger.jsonl` rows carry `seconds`, `finished_at` and
      `evaluated_at`. `seconds` is whole-job wall (tracking plus adjudication plus reap latency);
      `evaluated_at` is stamped inside the verdict payload, i.e. at adjudication END. There is no
      adjudication-START field. If no field pair brackets the adjudication step, per-clip adjudication
      wall is NOT recoverable from the rows and this is reported as such.
  (b) LOG TIMESTAMPS. If the daemon log lines carry no timestamp, reconstruction from the log timeline is
      not available and this is reported as such.

PRIMARY METHOD (used when neither (a) nor (b) yields adjudication wall). Adjudication runs in a Python
`threading.Thread` inside the daemon process; tracking runs in child processes. A read-only sample of
`/proc/<daemon pid>/task/` therefore separates them. The sampler runs from the operator machine over
ssh, reads only, writes nothing on the pod, and never signals the daemon:

  - cadence: one sample every 10 seconds for 10 minutes (61 samples planned);
  - per sample: wall epoch, `/proc/<pid>/stat` fields 14/15 (utime, stime, clock ticks) and field 20
    (thread count), the daemon child pid list, and the full thread-id list under `/proc/<pid>/task/`;
  - thread classification: thread ids present in EVERY sample are the persistent interpreter/BLAS pool.
    A thread id that appears after the first sample and/or disappears before the last is TRANSIENT. Each
    `_begin_adjudication` starts exactly one thread, so transient thread ids are the adjudication threads.
  - adjudication wall per thread = (last sample containing the id) minus (first sample containing it),
    resolution plus or minus one cadence interval (10 s). A thread present in every sample is
    right-censored and reported as censored, never as a completed duration.
  - concurrency = the count of transient thread ids alive in the same sample; reported as a
    per-sample series with its maximum and the number of samples at each level.
  - CPU share = (delta utime plus delta stime) in clock ticks divided by the sample span, expressed as
    cores, attributed to the daemon process only. The cgroup quota (`cpu.max`) is quoted alongside so
    the share is read against the real ceiling, not against `nproc`.

Distributions are reported as median, p90 and max, each with its n and its method label. Every timing
cell states which of the three methods produced it.

## 3. Cap design and its default-off rule

The cap ships as a NEW module under `scripts/platformkit/`; `track_daemon.py` is allow-listed at 440 lines
and MUST NOT grow, so it gains only a few call lines. The cap is a counting semaphore around the
adjudication step, exposed as an opt-in `--adjudication-slots N`.

DEFAULT-OFF RULE, binding. The default value means NO CAP and byte-identical behaviour to today: with the
flag absent, no semaphore is constructed, no acquire or release is executed, and the number of concurrent
adjudications is unbounded exactly as it is now. Every existing flag, default, ledger field, status string
and printed line keeps its name and its meaning (contract B2). The ledger row is identical in both modes.
No threshold, no bar and no default is moved by this row.

## 4. Estimate formula (an ESTIMATE, never a measurement)

Let A = measured adjudication CPU cores attributed to the daemon process, W = the workers setting, Q =
the cgroup quota in cores, T = median tracking wall seconds per clip, and D = median adjudication wall
seconds per clip. Then, per clip, occupancy without the cap is (T plus D) worker-slot seconds while only
T is tracking, so the slot-time fraction spent not tracking is D / (T plus D), and the CPU the box spends
on adjudication concurrently with tracking is A cores out of Q. Estimated clips per hour at W workers is
3600 * W / (T plus D) uncapped, versus 3600 * W / T for the tracking step alone; the capped case bounds
concurrent adjudications at N and so bounds the adjudication CPU at (N / observed max concurrency) * A.

This is labelled ESTIMATE FROM MEASURED PER-CLIP CPU everywhere it appears. The real before/after needs a
deployment this row does NOT perform, and no throughput result is asserted.

## 5. Verdict rule

DONE requires ALL of: the premise reproduced from the logs with n and a verified workers value; the trace
carrying real `file:line` citations; every timing cell carrying its n and its method; the cap opt-in,
additive and default-off; and the named per-file tests passing. Any of these missing yields PARTIAL with
the explicit list of what is missing. A FALSE premise yields PREMISE FALSE and no cap.

## 6. Honest limitations, stated in advance

The pod daemon runs older code than master (the G329 fix is undeployed); concurrency reconstructed from a
10-second sample is approximate to that cadence; the cgroup is shared with other lanes scorers, so CPU
seconds are attributed to the daemon only where `/proc` says so; a thread alive across the whole window
is censored; and no clips-per-hour figure is claimed until the cap is deployed and measured.
