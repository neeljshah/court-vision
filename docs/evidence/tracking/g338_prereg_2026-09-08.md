# G338 detector input decision preregistration

Spec: `docs/evidence/tracking/specs/G338_spec.md`, VERSION 2026-09-08b. Contract:
`docs/evidence/tracking/VERIFIER_CONTRACT.md`, sections A and B. This is a tracking
screening measurement, not a predictive-loss comparison; no evaluator loss or calibration
claim is defined by the spec.

## Before condition and stopping rule

Before any arm x section plausibility comparison, run the exact binding condition on one
sealed section and its same sealed frame indices: the 1920 arm emits at least 1.5 times the
640 arm's in-frame person rows. If the ratio is below 1.2 on two sections, the premise is
FALSE. Only those two rerun records can establish that result. Otherwise execute all arms.

## Sealed source and frame selection

`snapshot` enumerates one corpus path at a time, records each opened source's absolute path,
byte size, WxH, frame count and SHA-256, and ranks candidates by SHA-256 of basename plus
the salt `G338-2026-09-08b`. It takes two distinct-game 1920x1080 sections, two distinct-game
1280x720 sections, then the next two distinct-game sections at height at least 720, without
reusing a path. If fewer than two sources exist at either required resolution, it records that
fact and does not silently substitute a resolution. For a source of F frames, n is 60 and
stride is max(1, F // 60); offset is int(SHA-256(basename + salt)[0:8], 16) % stride; indices
are offset + i*stride for i in [0, 59]. The snapshot manifest is written before detector work.

## Arms and fixed route settings

Every sealed frame is supplied to 640, 960, 1280 and 1920 arms using the same deployed
`yolov8n.pt` weight, person class [0], route confidence, device and precision. A 640 2x2 tile
arm runs only when requested and is reported separately. The only arm difference is image
size (or the declared tiling). Each frame is one stable evaluator-state key:
`<section_sha256>:<frame_index>:<arm>`; no game-level state substitutes for its ticks.

## Metrics and decision rule

For every arm x section, report n frames, n boxes, detector ms/frame and peak GPU MiB. A
person box counts for players-per-frame only when its unpadded rectangle intersects the decoded
frame; referees and bench can remain, so the 8--13 band share is screening only. Report median,
p10 and p90 players/frame and its 8--13 band share; height share in 5.5--7.5 ft from the
fallback route homography; wholly-in-frame share; court-polygon share from that same fallback
homography; persistence share (IoU at least 0.5 for at least three consecutive sampled frames);
and raw ball-class detections/frame when available. The homography-derived height and court
measures are explicitly caveated as fallback-homography proxies.

The recommended input size is the smallest imgsz whose plausibility (players band share,
height share, wholly-in-frame share, court-polygon share, persistence share) is within 5 pct
of the best arm on at least 4 of 6 sections and whose ms/frame keeps the daemon's 8-worker
throughput (at least 0.8x of the 640 arm's clips/hour estimate per G328's formula). Ball count
is reported, not decided. The delta convention, where a comparison is printed, is baseline
loss minus candidate loss: positive means candidate better. No loss is defined for these
plausibility shares.

## Boundaries

Heavy detector work runs only as pod scratch under `/workspace/wt/a20/` through
`/c/Users/neelj/bin/pod_run a20 --ship ... --fetch ...`; it never writes the deployed tree,
data, data/registry, the register or ledgers, and it never signals the daemon or guards. The
pod command records Python and library versions plus SHA-256 for every exercised route/module.
No flag default changes. If a result later differs from 640, a separate default-identity test
must precede an opt-in hook. Limitations: plausibility is not accuracy; fallback homography can
be wrong; six sections are screening; throughput is an estimate.
