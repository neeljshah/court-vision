## The sealed SELECTION RULE

Executed once, at run time, against
`/workspace/nba-ai-system/data/footage_corpus`:

1. List every `*.mp4` in that directory.
2. Probe each with a SINGLE combined `-show_entries` call and keep those with
   **width >= 1280** (this excludes the 640x360 tier, a different capture regime).
3. Sort the survivors by **mtime DESCENDING** -- newest first, because the newest arrivals
   entered the tracking queue last and are the least likely to be deleted mid-run.
4. Walk that order and take the FIRST clip of each distinct GAME ID, where the game id is
   the file stem up to and including the last `_s<digits>` segment removed, until **3
   distinct game ids** are collected.
5. **FATAL if fewer than 3 qualify.** No substitution, no relaxation, no retry at a lower
   width.

**IMMEDIATE SNAPSHOT.** Each selected clip is probed for its last decodable index by the
readable-anchor rule (binary search on the real cv2 seek path, never ffprobe's
`nb_frames`), 40 evenly spaced indices spanning 0 .. anchor are decoded AT ONCE with
`TOPCUT` applied, and the decoded arrays are held for the whole run so **every arm sees
byte-identical frames**. The SHA-256 of each decoded frame and of the whole stack is
recorded, so the exact construct is reproducible from the artifact after the clip is gone.
A failed frame read is FATAL, never dropped.
