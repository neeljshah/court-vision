## 0. Scope, sign convention, and what this row is not

This row decides, for each image-space gate that rejects the UNCHANGED arm in
G358, between two competing explanations of the same measurement:

    PRODUCTION_SCHEMA_ARTIFACT  the gate reads rows the production row builder
                                wrote on every frame while positions advanced
                                only on evaluated ticks
    THRESHOLD_MISCALIBRATED     the gate reads live motion and the sealed
                                threshold sits inside the live distribution

It is a calibration-diagnosis row on non-scorable image-pixel rows. It certifies
no court geometry, no tracking quality, no ownership and no forecast, and it
carries no monetary interpretation of any kind. Every adapter output row keeps
`scorable=False`.

Sign convention. `held_share` is a share of comparable consecutive row pairs;
higher means more held rows, which is the defect this row tests for. For an arm
statistic, `rejection_share = rejected_n / evaluated_n` with `evaluated_n`
counting PASS and REJECT only. On A0 a HIGHER rejection share is WORSE (false
rejection). On A1_FROZEN, A2_ID_MERGE and A5_BALL_SHIFT a HIGHER rejection share
is BETTER (detection). A displayed delta is M1 minus M0, so for a detection cell a
positive delta means the collapsed arm detects more. Wilson bounds are two-sided
95 pct and are stored as additive integer per-mille columns,
`permille = round(1000 * share)`.

## 2. PREMISE (step 0, binding before-condition)

Measured by `premise`, per sealed section, on `tracking_data.csv` read as TEXT
(every field a string; no float parsing, so "byte-identical" is literal):

    rows                  data rows of the section table
    unique_frames         distinct values of `frame`
    tracks                distinct values of `player_id`
    pairs_n               comparable consecutive pairs = rows - tracks, counting
                          one pair per adjacent row pair WITHIN a track after a
                          stable sort by (player_id, frame); the first row of a
                          track has no predecessor and is not a pair
    held_n                pairs whose `x_position` AND `y_position` strings are
                          byte-identical to the previous row of the same track
    held_share            held_n / pairs_n; 0.0 when pairs_n is 0

A row with an empty or non-numeric position string is compared as the literal
string it carries, so it can be held; it is never dropped. The denominator is
`pairs_n`, never the count of rows that happen to repeat (contract H1, B9).

Stride, reported beside the held share, from the ledger record with the LATEST
`finished_at` for that `game_id` in `data/tracking/track_daemon_ledger.jsonl`
(S4: file and field named):

    ledger_rows, ledger_seconds, ledger_source_fps, ledger_decoded_frames,
    ledger_evaluated_frames, ledger_stride     -- verbatim ledger fields
    implied_stride        = ledger_decoded_frames / ledger_evaluated_frames
    modal_frame_step      = the modal positive difference between consecutive
                            DISTINCT `frame` values of the section table

`ledger_seconds` is reported verbatim and is NOT interpreted as content length: on
the sections inspected while writing this prereg it disagrees with
`source_duration`, so no stride is derived from it. A missing ledger record leaves
every ledger column empty and the section keeps its held share.

PREMISE FALSE rule, sealed: if `held_share < 0.20` on EVERY section of the sealed
list, positions are not held, the gates read live motion, and the row STOPS -- the
finisher writes the memo with the table, commits, and reports PREMISE FALSE. The
reseal question then belongs to a threshold row, not this one. Otherwise the row
proceeds to section 3 on the full sealed list (no section is dropped for a low
held share; the premise is a property of the SET, per contract S2).

## 3. The two adapter arms

Both arms use the LANDED `production_schema_adapter.adapt_production_section` and
the LANDED `g358_gate_execution` constructors by IMPORT. Neither module is edited
by this row, so the G358 adapter stays byte-identical for every other reader (B2,
B10); the collapse lives in `g359_held_position.py` alone.

    M0  rows as written. adapt -> construct_arm(arm) -> evaluate. This is the
        G358 FULL-duration behaviour exactly.
    M1  evaluated ticks only. adapt -> construct_arm(arm) -> COLLAPSE -> evaluate.

COLLAPSE rule, sealed. Over PLAYER rows only (`cls == "player"`), taken in a stable
sort by (`track_id`, `frame`): a row is HELD when its `x` equals the previous row
`x` AND its `y` equals the previous row `y` under exact float equality within the
same `track_id`. Every HELD row is DROPPED; the first row of each held run is
KEPT; every non-held row is untouched; the surviving rows keep their original
table order and every column value unchanged. NaN never compares equal, so a row
with a missing coordinate is never collapsed. Ball rows (`cls == "ball"`,
`track_id == -1`) are NEVER collapsed: the measured defect is a player-position
defect, and leaving the ball rows alone keeps the ball gates and the A5 plant
comparable across the two arms. `held_rows_dropped` is recorded per (section, arm,
mode).

PLANTS BEFORE COLLAPSE, sealed: `construct_arm` runs BEFORE the collapse in M1, so
A1_FROZEN, A2_ID_MERGE and A5_BALL_SHIFT are planted into the uncollapsed table
and the mode cannot hide a plant. A0 is the unchanged arm.

GATES UNCHANGED, sealed: `evaluate_image_space` is called with the same sport
(`basketball`), the same `frame_width` / `frame_height` / `frame_size_source` the
adapter returns, and the same landed thresholds, in BOTH modes. Zero thresholds
are moved by this row (Q3, B10).

DURATION: FULL only. The three gates this row is about are FULL-duration cells in
the G358 `diagnosis.csv`, and the duration sweep is already landed there.

## 4. Denominators, raw and collapsed

The collapse changes the denominator of every per-frame statistic, so BOTH are
recorded per (section, arm, mode) row of `arms.csv`:

    rows_total, player_rows, ball_rows, tracks, unique_frames,
    steps_n = player_rows - tracks, held_rows_dropped

`steps_n` is the denominator of `zero_step_share`; `player_rows` is the
denominator of `distinct_position_ratio`; `tracks` is the denominator of
`stationary_track_share`; `unique_frames` is the denominator of
`coverage_attempted_frames` and of the ball-presence gates. A comparison of two
shares across modes is a comparison across DIFFERENT denominators and the memo
states that in the same sentence as the numbers.

## 5. Decision rule, per failing gate (sealed)

The gate set is every gate listed in the landed G358 `diagnosis.csv` (FULL, arm
A0, rejection share above 0.05): `zero_step_share`, `distinct_position_ratio`,
`stationary_track_share`, `median_step_distance`. The first three are the three
gates this row exists for; `median_step_distance` is carried because it is in the
same landed table and its direction is opposite (section 11).

Denominator: PAIRED sections. A section enters the decision for a gate only when
that gate has status PASS or REJECT for arm A0 in BOTH modes. `n_paired` is
printed and is the denominator of every share in `decision.csv`.

    clear_share_M0  = sections with status PASS for A0 under M0 / n_paired
    clear_share_M1  = sections with status PASS for A0 under M1 / n_paired
    reject_share_M1 = 1 - clear_share_M1

Applied IN THIS ORDER, so the boundary at exactly 0.10 is deterministic:

    1. clear_share_M1 >= 0.90 AND clear_share_M0 < 0.90
                                  -> PRODUCTION_SCHEMA_ARTIFACT
    2. reject_share_M1 >= 0.10    -> THRESHOLD_MISCALIBRATED
    3. otherwise                  -> UNDECIDED

UNDECIDED is reached when M0 itself already clears on at least 90 pct of the
paired sections, that is when the gate is not a live rejecter on this set, so
neither explanation is under test. It is a valid, reportable outcome.

The unchanged sealed threshold is used in BOTH modes; class 1 means the gate
clears under M1 with NO threshold move, and the fix is the adapter mode.

## 6. Candidate v2 threshold (additive, unscored here)

For a gate classified THRESHOLD_MISCALIBRATED, `decision.csv` PREREGISTERS a
candidate threshold BESIDE the sealed one, never in its place, in additive columns
`candidate_v2_threshold`, `candidate_v2_quantile`, `candidate_v2_gate_name`
(`<gate>_v2`). The value is a quantile of the A0/M1 measurement distribution over
the paired sections, direction-aware, with the direction read from the landed
`liveness_metrics.thresholds_for("basketball")` key suffix and never hand-copied:

    direction max (reject when value > threshold)  -> quantile 0.95
    direction min (reject when value < threshold)  -> quantile 0.05

computed with `pandas.Series.quantile` under the numpy default linear
interpolation, matching G358 fix 1c. A gate with no direction key leaves the
candidate columns empty. NO threshold is moved, no flag is flipped, and no
candidate is scored by this row: a later row scores it on a FRESH sealed set,
never on this one.

## 7. Detection bar (sealed)

For A1_FROZEN and A2_ID_MERGE, `any_gate` detection at FULL must be >= 0.80 in
BOTH modes, denominator the sections where the arm was constructible and reached a
status. A5_BALL_SHIFT is REPORTED, not barred: G358 measured its FULL detection at
0.382 and found it identical to A0 in every FULL cell, and G357 measured ball rows
on a minority of frames, so this row inherits that LIMIT rather than re-testing
it. A detection figure below the bar is reported as a LIMIT of the arm, and never
lowers the bar (Q3).

## 9. Byte-identical default-output check

`check-default` re-aggregates the M0 records with the LANDED
`g358_gate_execution.aggregate_gates` and compares every produced cell, as the
formatted string it writes, with the landed
`g358_full_section_gate_execution_v2_2026-09-08/gates.csv` row of the same
(arm, duration, gate) key, restricted to duration FULL and to the four
constructible arms (A3_SCALE_TRANSLATE and A4_MIRROR are UNIDENTIFIABLE in G358
and are not produced here). It prints the compared-cell count and every mismatch,
and exits non-zero on any mismatch. A clean run is the evidence that M0 reproduces
G358 exactly and that the collapse touched nothing outside M1.

## 10. What the finisher may not conclude

Thirty-four sections are a screening on one snapshot of a rotating corpus. A class
from this row is a statement about THESE sections under THESE landed thresholds,
never a property of the tracker. The two modes have different denominators
(section 4). The candidate v2 thresholds are unscored. A5_BALL_SHIFT remains
limited by ball-row coverage. Image-space gates are necessary and never sufficient
for court geometry: `frame_size_source` is absent on these sections, so
`g325_wholly_off_frame`, `oob`, `jump_max`, `jump_p95`, `coordinate_contract`,
`attempted_frames` and `coverage_attempted_frames` do not reach a bar in either
mode, exactly as in G358.

## 11. Analytic predictions, stated before the run

These follow from the landed metric definitions in
`scripts/platformkit/liveness_metrics.py:compute_liveness_metrics` and are stated
here so that the finisher confirms or falsifies them rather than discovering them:

    stationary_track_share is INVARIANT under the collapse. Its statistic is the
    share of tracks whose summed step distance is below 0.50, and a dropped held
    row removes a step of length exactly 0, which cannot change a sum. If the
    measured M1 value differs from M0 on any section, the collapse has a defect
    and the finisher reports that section rather than the class.

    zero_step_share and distinct_position_ratio move AWAY from their sealed
    thresholds under the collapse (zero steps leave both the numerator and the
    denominator; the position denominator shrinks while the distinct positions do
    not), so class 1 is reachable for them.

    median_step_distance moves TOWARD its sealed threshold under the collapse: it
    is a max-direction gate at 8.408436 and removing zero steps raises the median.
    Its M1 rejection share may therefore be HIGHER than M0. That is an honest
    result, is reported as such, and does not license moving the threshold.
