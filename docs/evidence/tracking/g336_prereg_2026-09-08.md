Purpose: measure reusable-slot fragmentation on four production-route sections and compare a
harness-only, slot-cap-free association on the identical detector observations. This is a
label-free screening measurement, not an identity-ground-truth or player-quality claim.

Binding premise: each section is run once through `scripts/run_clip.py` and its unmodified
`UnifiedPipeline` production tracker. `player_id` is measured as a reusable slot; instances use
G310's fixed key (gap <= 270 source-frame ids and bottom-centre step <= 0.20 times source height).
If median instance length exceeds 40 frames on at least three sections, the premise is FALSE and
the run stops without comparison.

The detector recorder wraps the existing production fallback association only to write each
per-frame detector observation once: section, source frame, team, score, bbox, HSV signature, and
the production-assigned slot. It neither changes detector output nor tracker state. The baseline
is that assigned-slot sequence. Candidate association is offline, team-separated, unbounded in
track count: Hungarian cost `0.75*(1-IoU)+0.25*(1-cosine(HSV))`, accept cost <= 0.75, active age
30 evaluated ticks, and new id for each unmatched observation. Sensitivity is one fixed pair:
accept cost <= 0.80 and active age 45. No other sensitivity or parameter selection is allowed.

Per section, report all observations and: fragmentation ratio = instances / (evaluated frames x
10); median and p90 instance length; next-frame, <=3-px end/start cross-instance switch proxy;
mean within-instance cosine and mean between-instance cosine; share of evaluated frames with >10
recorded detector observations; and milliseconds per evaluated frame. Improvement means baseline
loss minus candidate loss, so a positive fragmentation delta means the candidate has lower loss.

Every scored tick is one stable evaluator state keyed by `section:source_frame`. The run uses
`scripts/platformkit/eval_gate/cpcv_engine.py:cpcv_evaluate` with frozen four-section groups,
one test group, `embargo_days=1`, its symmetric purge, and state-key guarding. Evaluator records
are archived before section aggregates; no per-game surrogate states are allowed. The comparison
has no fitted model: the evaluator exposes the precomputed per-tick arm loss for its redacted test
state, preserving the required purged and symmetric-embargo audit path.

Acceptance bar copied verbatim from G336: the variant reduces fragmentation ratio by >= 30 pct on
at least 3 of 4 sections WITHOUT raising switch proxy or lowering within-instance appearance
similarity on those sections; runtime <= 2x. Any production hook is <=15 lines, behind
`TRACK_ASSOC_V2=0`, and is added only if this bar is met. The default remains OFF.

Known limitations: no identity ground truth exists; fewer, longer instances can be wrong merges;
the switch and appearance checks are only proxies; four sections are screening; and OSNet-style
appearance on 720p-or-smaller crops is weak for same-team players. The route files hashed in the
memo are `src/pipeline/unified_pipeline.py`, `src/tracking/advanced_tracker.py`,
`src/tracking/osnet_reid.py`, and the new harness file.
