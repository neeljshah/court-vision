## 1. PREMISE (step 0, binding before-condition)

`census` counts, over EVERY ledger row and EVERY `<game_id>/tracking_data.csv` header (head to tail,
no sampling, no head slice): the ledger rows present per field of `game_id, finished_at, seconds,
rows, decoded_frames, evaluated_frames, stride, source_duration, probe_status`, and the table headers
carrying each of the six COMPLETE-BINDING columns `source_sha256, source_first_pts, source_fps,
source_width, source_height, source_topcut_px`.

A table carries a COMPLETE SOURCE BINDING when all six columns are present in its header. The
premise is FALSE when `tables_complete_binding / tables_readable >= 0.95`: the map already exists,
the row STOPS at this section, the memo reports PREMISE FALSE with the two counts, and no source is
fetched. Below 0.95 the row proceeds. A table whose header cannot be read is counted as
`tables_unreadable` and is never silently dropped from the denominator (contract H1, B3).

## 2. JOIN CLASSES (exact definitions, fixed here)

One row per distinct ledger `game_id` in `ledger_links.csv`, carrying `run_start_utc = finished_at -
seconds` in UTC, `table_sha256` of `tracking_data.csv`, `ball_table_sha256` of `ball_tracking.csv`,
and `deploy_manifest_sha256` (the digest of `deploy_manifest.json` or `code_identity.json` in the
game directory when such a marker exists, else `UNKNOWN` -- never inferred; contract A11).

- EXACT -- the source bytes are still present and hash-bound: `sources.csv` holds a row for this
  `game_id` whose `source_sha256` is a 64-character digest computed from the file itself, AND the
  archived table is readable.
- ALIGNED -- the source bytes are gone, but the same id and offset were re-fetched and every
  landmark of section 4 came back within the bar of section 3.
- UNKNOWN -- everything else, with the reason recorded in its own column: `table_unreadable` when the
  archived table cannot be read, `no_source_bytes_and_no_alignment` otherwise. An UNKNOWN row STAYS
  UNKNOWN. It is never promoted by resemblance of id, offset, duration or resolution.

The classes are exhaustive and mutually exclusive, evaluated in the order UNREADABLE, EXACT, ALIGNED,
UNKNOWN. The reported completeness is `rows in ledger_links.csv / distinct ledger game_ids`, so the
denominator is the ledger and not the classified set (contract B1, B9).

## 3. THE BAR (fixed here, never moved -- contract Q3)

Per landmark, temporal error = `(re-fetched presentation stamp at the archived frame index) minus
(archived tick timestamp)`, converted to native frames by the re-fetched stream rate. Sign
convention: POSITIVE means the re-fetched decode runs LATER than the archived tick. A section passes
only when EVERY one of its landmarks satisfies `abs(error) <= 1.0` native frame. One landmark outside
the bar fails the whole section, and the section stays UNKNOWN. A landmark whose archived frame index
lies past the end of the re-fetched decode is a FAIL, never a skip.

## 4. LANDMARK RULE

For one section, the evaluated ticks are the DISTINCT `frame` values of the archived
`tracking_data.csv`, each with its recorded `timestamp`, in ascending frame order. At least 30 of
them, evenly spaced by the rule of section 5, are compared against the re-fetched decode; the whole
per-landmark series is archived in `alignment.csv` (game, landmark index, archived frame, archived
timestamp, re-fetched stamp, rate, re-fetched file digest, error in native frames, within-bar flag),
so the verdict is recomputable from the artifact alone (contract Q9). A section with fewer than 30
distinct evaluated ticks is INELIGIBLE and is recorded as such, never padded.

## 5. EVEN-SAMPLING RULE (the complete eligible set, no head slice -- contract B7, A3)

The eligible set is every row of `ledger_links.csv` passing all three census checks, which are
archived per row in `sample_census.csv` alongside the eligibility flag: `table_readable`
(`table_sha256` is not UNKNOWN), `video_id_parsed` (the `game_id` splits into an 11-character source
id and an integer offset), `run_start_known` (`finished_at` and `seconds` both present). The set is
sorted by `game_id`, then: if `n <= 40` take ALL of it; otherwise take every k-th element with
`k = floor(n / 30)`, keeping the WHOLE stepped list rather than truncating it back to 30. Stepping
spans the first and the last element by construction. The same rule picks the landmarks inside a
section. No other selection is permitted, and the sample is never re-drawn after a result is seen.

## 6. COLLISION

A COLLISION is two or more DISTINCT ledger `game_id` values resolving to the same `(source id,
requested start offset)` pair -- for example a tagged `<tag>-<id>_s<offset>` and an untagged
`<id>_s<offset>` naming one section. Every collision is listed by pair with its full member list in
`summary.json`; a collision is reported, never resolved by preference, and both members keep their
own class. Zero silent collisions means the list is emitted whether or not it is empty.

## 7. VERDICT RULE

- DONE when: every distinct ledger `game_id` has a class; the collision list is emitted; at least 30
  sections across at least 10 distinct source ids are EXACT or ALIGNED with every landmark within the
  bar; every UNKNOWN carries its reason.
- PARTIAL, naming exactly what could not be proven, otherwise.
- PREMISE FALSE stops the row at section 1 with the two counts.

## 8. STATED IN ADVANCE, NOT DISCOVERED

The module makes no network call; the finisher fetches with yt-dlp itself and passes the resulting
path in. Sameness of id and offset is NOT evidence of sameness of bytes, and this row never asserts
it. The map is a provenance record; it measures no tracking quality and improves no forecast. No bar,
threshold, gate, flag, register row, ledger row or archived table is moved. Language is calibration
language only (contract Q6); an UNKNOWN-heavy outcome is an honest result, not a failure.
