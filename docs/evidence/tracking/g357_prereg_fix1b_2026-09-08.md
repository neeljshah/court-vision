# G357 preregistration - fix 1b, even-sampled reseal (2026-09-08)

Scope: amendment to `g357_prereg_2026-09-08.md` after verifier REJECT on B7 (the sealed list took the
first 30 of 32 eligible windows in ledger order, a prohibited head slice; `G357_VERIFY_2026-09-08.md`).
This artifact stands alone with its own seal; it does not edit or re-seal the original prereg. Cites
`docs/evidence/tracking/VERIFIER_CONTRACT.md`, especially B7, B10, Q1, Q3, Q8.

Census rule (unchanged from the original prereg, restated for a standalone seal): read
`/workspace/nba-ai-system/data/tracking/track_daemon_ledger.jsonl` once, read-only, in ledger order.
A candidate is eligible when its ledger record has `status == "tracked"`, a derived start
`finished_at - seconds > 1788904286` (the G354 deploy epoch; the ledger carries no `started_at` field),
`sport` in the basketball set `{nba, wnba, ncaa_basketball, basketball}`, and its `ball_tracking.csv`
header contains both `ball_x2d_px` and `ball_y2d_px`.

Archive rule (new; closes the verifier's NEW GAP): before selection, write `census.csv` with one row per
candidate that clears the status/epoch/sport prefilter (eligible or not), carrying every binding
eligibility field so the set is independently reproducible without re-querying the rotating ledger:
`game_id, base_game_id, sport, competition, status, finished_at, seconds, start_epoch, px_header_present,
rows, eligible`. `start_epoch` is the derived `finished_at - seconds`; `eligible` is 1 iff
`px_header_present` is 1 (status/epoch/sport already hold for every row in this file by construction).

base_game_id rule (new): `base_game_id` strips a trailing `_s<digits>` segment-clip suffix from `game_id`
(regex `_s\d+$`), leaving the base video id (e.g. `fiba-jFUMvm_epUE_s5410` -> `fiba-jFUMvm_epUE`;
`1zPhldjbJnU_s90` -> `1zPhldjbJnU`). `game_id` itself is never changed. Any reported game/video count is
labelled a base-video-id count, not a "game" count.

Competition rule (new, disambiguates the verifier-measured 7-competition figure from a naive prefix
regex): if the segment of `game_id` before its first hyphen matches a known league token
(`nbl, euroleague, gleague, fiba, lnb, eurocup, ncaaw, acb, cba, bleague, upco`, case-insensitive), that
token is the competition; otherwise the competition is the ledger's own `sport` field. This avoids a
false-positive single-letter prefix match against a bare YouTube-style video id (measured on this ledger:
`sport=nba` game ids incidentally matching `^E-`, `sport=ncaa_basketball` ids matching `^N-` or
`^GNjSxoeDT-`).

EVEN SAMPLING rule (replaces the rejected first-30 head slice; the only changed selection mechanic):
enumerate the COMPLETE eligible set (post-epoch, tracked, basketball, px header present) at seal time, in
ledger order, giving n. If n <= 40, take ALL n as the sealed sample. Otherwise take every k-th window with
`k = floor(n / 30)`, starting at index `start = floor((n mod 30) / 2)` (0-based indices into the eligible
list), i.e. indices `start, start + k, start + 2k, ...` while the index stays below n. This yields >= 30
windows spread from near the start to near the end of the whole set, never a contiguous run from index 0.
The resulting n (both the eligible-set size and the sampled count) is stated in the result memo, along with
the first and last sampled index, before any join or state-machine step runs.

Selection: before a state-machine run, commit `sealed_windows_fix1b.csv` (this file, plus `census.csv`)
together, as their own commit, separate from and after this sealed prereg commit. Each row names the full
tracking and ball paths, their SHA-256 values and byte sizes, source dimensions, `game_id`, the additive
`base_game_id`, competition, start/end frame (600/659, the unchanged G344 window rule), and a stable
`window_id` (equal to `game_id`, unchanged from the original prereg's convention).

Pixel join, state and survival rules: UNCHANGED from `g357_prereg_2026-09-08.md` verbatim -- only a finite
`ball_x2d_px,ball_y2d_px` pair populates `join_source=px`; a missing header counts as `missing_px_header`,
a present header with a non-finite pair counts as `missing_px_coordinate`; the G351 span-ratio sanity print
(flag > 1.5 either axis) is unchanged; the old court-map arm runs on the same sealed windows for survival
diagnostics only. G344 keeps radius `60 * source_height / 720`, 10px ambiguity margin, 3-frame history,
cosine >= 0.5, ratio [0.5, 2.0], MAX_AGE 30, cut protection -- byte-identical. G349 stages, both full-frame
and eligible-pair denominators, the observed/inferred ablation, and the unshifted/-30/+30-frame shuffle
control with its unchanged >=200-per-mille (20pp) drop bar are all unchanged. The unchanged >=100 eligible
observed-ball motion-pair bar and the unchanged >=30 windows / >=3 base-video ids / 2 competitions bar are
reported met or not met, never moved.

Outputs: `survival_fix1b.csv` and `states_fix1b.csv` are NEW, ADDITIVE files (same column contracts as
`survival.csv` / `states.csv` plus `join_source`, `ratio_x`, `ratio_y`); the rejected first-30 artifacts
(`sealed_windows.csv`, `survival.csv`, `states.csv`) are left in place, unedited, for the record.
