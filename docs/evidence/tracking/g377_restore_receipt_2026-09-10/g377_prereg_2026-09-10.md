## 3. Manifest rule (deterministic, no inference)

A file enters a closure's manifest by exactly one of two mechanical rules. Nothing enters by judgement,
and a path that cannot be resolved is recorded UNRESOLVED and named, never dropped.

RULE M1 -- MEMO-NAMED. Scan the closure's landed memo `.md` line by line for every token matching a
path regex: a run of `[A-Za-z0-9_./-]` that either contains a `/` or ends in one of the extensions
`.csv .json .jsonl .md .npz .parquet .pt .pth .png .jpg .svg .sha256 .txt .py`. Each hit records
`required_by = <memo path>:<line number>`.

RULE M2 -- READER-OPENED. Scan each reader module line by line for every single- or double-quoted
string literal that contains a `/` or ends in one of the same extensions. Each hit records
`required_by = <module path>:<line number>`. Reader modules take most inputs through argparse, so an
M2 hit is usually a basename (`recovery.csv`) or a relative fragment; it is resolved against the
closure's evidence directory, then against the repository root.

RESOLUTION order for a raw token, first hit wins: (a) repository-relative path that exists on master;
(b) the closure evidence directory joined with the token; (c) repository root joined with the token;
(d) an absolute POSIX path (`/workspace/...`) is recorded as POD_ABSOLUTE and is never resolved
locally; (e) otherwise UNRESOLVED.

DEDUPE by resolved path within a closure; every `required_by` reference is kept and joined with `|`,
so one row can carry both an M1 and several M2 references. A directory-only token (`sheets/dev/`,
`raters/`, `strips/`) expands to every file under it that is tracked on master, and the expansion is
recorded.

ROLE, assigned from the resolved path by fixed prefix and suffix rules, for reporting only: `prereg`
(a `*prereg*.md`), `code` (`scripts/` or `src/` `.py`), `test` (`tests/`), `ledger` (`*ledger*.jsonl`
or `RESULTS_LEDGER.md`), `native_pixels` (`.jpg .png .svg`), `weights` (`.pt .pth`), `reference`
(a rating, adjudication, label or agreement artifact), `prediction` (a predictions, scores, arms,
decisions or confusion artifact), otherwise `artifact`. A role is a label; no bar depends on it.

The manifest is `dependency_manifest.csv` with columns
`closure,path,role,required_by,rule,off_pod_source,present_off_pod,present_on_pod,bytes,digest`.

## 5. Byte-verification rule

Every restored file is written into `C:/Users/neelj/AppData/Local/Temp/g377_restore/<closure>/<path>`
and then verified, in this order:

    V1  GIT IDENTITY. `git hash-object --no-filters <restored file>` must equal the object id of the
        committed blob it came from (`git rev-parse master:<path>`). This is the binding check for
        every S1/S2/S3 file and it is byte-exact.
    V2  CONTENT DIGEST. sha256 over the raw restored bytes, and sha256 over the raw source bytes, must
        be equal. Recorded for every file including S4/S5/S6, where V1 does not apply.
    V3  LIVE-COPY COMPARISON. Where the same path still exists on the pod, `sha256sum` on the pod must
        equal the V2 digest. A pod path that no longer exists is recorded POD_ABSENT, which is a
        measurement, not a mismatch. V3 is reported for every file the pod still holds; the pod is read
        only and nothing is created there to make a comparison possible.

A file passes only if every applicable check agrees. A single V1 or V2 mismatch FAILS that closure --
the closure cannot be DONE -- and the mismatching path, both digests and the source are printed.
Results go to `restore_hashes.csv` with columns
`closure,path,source,git_oid_expected,git_oid_restored,sha256_source,sha256_restored,sha256_pod,bytes,verdict`.

## 7. Retention contract -- PROPOSAL ONLY

`PROPOSED_retention_contract.md` in the evidence directory. It is a proposal: nothing is wired, no
prune runs, no lifecycle changes, no flag moves, no `src/` hook, and the register is untouched. Its
required sections, fixed here so the proposal cannot be shaped by what the measurement happens to find:

    1. IDENTITY BEFORE PRUNE -- a prune candidate becomes eligible only after a receiver acknowledgement
       exists: an off-pod copy whose digest and successful READBACK are both recorded. Fails closed.
    2. RECEIVER ACKNOWLEDGEMENT -- the exact record a receiver writes: path, bytes, sha256, source,
       readback verdict, UTC. No acknowledgement, no eligibility.
    3. READER LEASES FOR SEALED SETS -- a sealed set names its readers; while a lease is open, no member
       of the set is eligible, regardless of age or quota pressure (D2).
    4. VERSIONED IDENTITIES -- a moved or re-supplied source gets a new version, never the old identity.
       A re-fetch is a new identity by construction.
    5. BYTE ledger -- an allowance derived from the roughly 41 GB measured quota and the roughly
       1.8 GB/h table growth, stating what fraction is spendable and at what growth rate the intake, not
       the evidence, is bounded first.
    6. WHAT THIS PROPOSAL DOES NOT DO -- it authorises no deletion, and it is not a claim that anything
       lost is recoverable.

VERDICT MAPPING, fixed now. DONE requires all four: every file present off-pod verified with 100 pct
digest and identity agreement; all four recomputed decisions equal to their archived values above;
`missing.csv` naming every absent file with the row it disables; zero replenished executions and zero
deletions. PARTIAL if any closure carries a missing required file or a decision that does not
reproduce -- the closure and the files are named on line 1. PREMISE FALSE applies to the recovery part
only, under the section 2 stop rule, and the readback-and-recompute part still runs and is reported.

EYE CHECK, fixed now: two files of role `native_pixels` per closure, drawn by taking the closure's
`native_pixels` rows in sorted path order and selecting index 0 and index floor(n/2) -- an even draw,
never a head slice (A3, B7). Each is copied from the restored scratch tree into `eye/` beside a row of

closure holds no camera pixels at all, the fact is stated in the memo and the two files are drawn from
its rendered artifacts instead; the substitution is disclosed, never hidden.
