# G386 preregistration: one-pass pin, copy, and receiver receipt

This preregistration is sealed before any live corpus census, capture, render,
or comparison. It prepares an infrastructure measurement only. The Claude
finisher performs the pod-side capture against the rotating corpus.

## Binding plan

1. Inventory every G379, G373, and G378 reader input and existing receiver
   receipt. Treat a manifest, retained native image, and retained replay source
   as distinct objects. If an existing tool proves one-pass capture plus
   receiver readback for 30 distinct sections, report PREMISE FALSE and reuse
   it. Otherwise census the complete available pool; fewer than 30 is
   preparation-only NOT VALIDATED.
2. Draw 30 distinct sections evenly over video/time from the metadata census,
   spanning at least 10 videos. Record every sealed attempt, including loss.
   Select each reader contract before opening: full replay source, or native
   target/context pixels for rating only.
3. For each attempt, open the selected pathname once, stream that same handle
   to bounded lane scratch while hashing it, and record SHA-256, byte count,
   ffprobe stream output for the captured copy, and the ledger snapshot line.
   Compare handle metadata before and after; mutation, short read, pathname
   replacement, and open failure are explicit non-CAPTURED statuses.
4. Send only the reader-required captured bytes and manifest to the receiver.
   The receiver writes a temporary object, independently reads it back and
   hashes it, probes requested pixels, and returns a versioned receipt.
   CAPTURED requires that receipt. A source lost between pin and copy is LOST;
   it is never substituted.
5. Keep total scratch below 2 GB and each staged batch at or below 1.5 GB.
   Release lane staging only after reader inventory, fulfilled leases, and a
   matching receipt. Run the five constructed scratch controls and export the
   fixed captured manifest twice; both exports must be byte-identical.

## Acceptance and reporting

The finisher reports 30/30 receiver-verified captures or explicit failed
attempts, exhaustive required-object coverage, receiver byte and pixel
agreement, zero false CAPTURED receipts, exact controls, and equal export
digests. Only complete coverage permits DONE. Otherwise the result is PARTIAL
or NOT VALIDATED. Delta sign convention for any later comparison is baseline
loss minus candidate loss; positive means candidate better. This preregistration
contains no scored comparison.
