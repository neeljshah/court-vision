## Binding framing (must survive into the UI verbatim)

This is **DECISION-SUPPORT, NOT a picks / profit / +EV / ROI product.** Every number is a
calibration measurement, **badged by SOURCE**. "MARKET-EFFICIENT HERE" is a first-class,
visible state -- a feature, not a failure. A visible disclaimer is always present.
`edge_claimed` is always `false`. NEVER render the retracted measurement artifacts
(`+18.38` / `0.119` / `+54` / `78.11` / `8.94` / `54.57`) outside an explicit retraction
context citing `docs/JOB_EVIDENCE_PACKET.md`.

Source badges (reuse these three exactly):
- `model-in-corpus` -- our calibrated forecaster, scored in its own corpus
- `devigged-market` -- the Shin-devigged closing line
- `score-only-anchor` -- the synthetic golden regression anchor (not a real claim)

## 1. Data contract (FastAPI / static)

The generator already emits the page; expose it as JSON for the SPA. Two zero-risk options:

**Option A (static, no backend change):** commit `docs/CALIBRATION_RECORD.md` (already
generated by `python -m scripts.platformkit.calibration_record --write`) and serve it as a
static asset; the SPA fetches and renders the markdown.

**Option B (JSON endpoint, additive route in the live app's own server -- NOT api/):**
have a small static-data step write `calibration.json` shaped like the generator's
`build_sections()` data, e.g.:


## 2. React/Vite: /calibration view (read-only)

Add a route + a `lib/calibration.ts` fetcher and a `components/board/CalibrationRecord.tsx`.
Sketch (TypeScript, adapt to the app's existing fetch + Badge primitives):

```tsx
// lib/calibration.ts
export type SourceBadge = "model-in-corpus" | "devigged-market" | "score-only-anchor";
export interface Bin { lo: number; hi: number; n: number; pred: number; obs: number; sparse: boolean; }
export interface LedgerRow {
  sport: string; market: string; n: number; brier: number; ece: number;
  market_brier?: number; dm_p?: number; verdict: string; source: SourceBadge;
}
export async function fetchCalibration() {
  const r = await fetch("/calibration.json");        // Option B; or fetch the .md
  if (!r.ok) throw new Error("calibration unavailable");
  return r.json();
}

// components/board/CalibrationRecord.tsx (sketch)
export function CalibrationRecord({ data }: { data: any }) {
  return (
    <section aria-label="calibration record">
      <Disclaimer text={data.disclaimer} />              {/* always visible */}
      {data.ledger.map((row: LedgerRow) => (
        <ReliabilityCard key={`${row.sport}-${row.market}`} row={row} />
      ))}
    </section>
  );
}
```

Each numeric cell renders a `<SourceBadge kind={row.source} />`. Verdicts containing
"MARKET-EFFICIENT HERE" render in a calm, neutral (not red/alarm) style -- it is the
expected, honest state. Bins with `sparse: true` render an explicit "low power (n<30)"
note so a reader never over-reads a point. A reliability bin can reuse the existing chart
primitive (predicted on x, observed on y, with the y=x diagonal).

## 3. The pregame -> live HERO interaction

On a game card, when a live in-game state exists, show the pregame and conditioned numbers
together as the hero line (consume `predict_matchup`'s pregame + ingame blocks):

```
Pregame 47% [devigged-market match]  |  Q3 +8: 71% [model-in-corpus, interval 64-77%]
```

Rules for the hero:
- ALWAYS show the pregame number AND its source badge first, then the conditioned number.
- The conditioned (in-game) number carries `model-in-corpus` and an interval, never a point
  promise. Label it "in-game conditioning (calibration)", never "edge" / "value" / "+EV".
- A persistent footnote: `edge_claimed: false -- decision-support, not a wager recommendation.`
- If no live state, show pregame only with "MATCHES the devigged close" framing.
