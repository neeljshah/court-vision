1 · Executive Summary

CourtVision is an AI-native NBA intelligence platform evolving into a domain-agnostic, multi-sport forecasting and decision engine. It turns raw sport data — including its own computer-vision tracking — into calibrated probabilistic predictions, validates every step against a brutal leak-free gate, and improves itself within hard honesty rails. It runs unattended, heals itself, and tells the truth about what it does and does not know.

Brain notes (1 graph)

The defining idea is the funnel: every data point is pushed through as many candidate signals as possible, the survivors feed models, the models feed one engine per sport, the engine emits one coherent prediction per market, and an intelligence layer plus an agentic loop re-validate the whole chain continuously. The funnel was originated here — building this kind of end-to-end, self-validating sports-detail pipeline is genuinely hard precisely because it has not been done this way before.

The honest north star

The product is a calibrated predictor, not a betting-edge product. The defensible win is matching the devigged closing line within noise on team-strength markets, plus a measured, calibrated in-game conditioning improvement. Beating the vig is not the goal; beating predictions — accuracy and calibration — is. An honest REJECT is a success, not a failure. No dollar edge is claimed anywhere.

What makes it unusual

  • It owns its data tier. A real CV pipeline (YOLO → homography → tracking → re-ID → events) produces possession-level micro-state most public models never see.
  • It is honest by construction. Hard-coded rails forbid fabricated edges, retracted numbers, dollar fields on the served product, and flag flips — even when running unattended for days.
  • It improves itself — carefully. A 5-gate ratchet can recalibrate the served model, but only on changes that survive walk-forward, multi-corpus, clustered significance testing; otherwise it ships nothing and says so.
  • It was built by an agentic pipeline directed by one human — Opus orchestrates and gates, a Sonnet fleet writes code, search agents explore — across ~1,470 commits.

Why the funnel is the hard, original part

Anyone can fit a model. That full sports-detail funnel — CV tier included — is what had to be invented from scratch.

4 · System Architecture

One command brings up a self-healing stack of 18 supervised daemons. Each has a heartbeat and an independent restart policy: if one dies it goes red alone and auto-restarts in seconds while the rest keep running.

Operational properties

  • Independent & self-healing. Kill any daemon → it returns in ~30s; kill the whole thing → clean stop leaves zero processes.
  • Stale-never-green. A hung or dead daemon reads RED, never falsely "fresh." Heartbeat freshness windows are tuned per daemon cadence.
  • Boot-on-login. A registered Windows task brings the whole stack up at logon via a watchdog that keeps the supervisor alive; governance preflight runs first; real money stays default-DENY.
  • Atomic writes on every shared artifact so a crash mid-write never corrupts the served state.

5 · The Prediction Engines

Each sport has exactly one engine producing one probability distribution. Every market — moneyline, totals, spread, sets, props — is read off that same distribution, so the served numbers are internally coherent by construction (and the code asserts it).

SportEngineOne distribution → many markets
NBAElo + possession-level Monte CarloWin prob, totals, spread off one possession sim.
MLBMargin-of-victory Elo + anchored Negative-BinomialRun-line at 0 = moneyline; totals partition asserted.
SoccerExponentially-weighted Poisson / Dixon-ColesAll markets off one Dixon-Coles score matrix.
TennisSurface-Elo + point-level Monte Carlo9 coherent markets off one MC matrix (sets, handicaps, scores).

Coherence is enforced, not hoped for

The producer asserts served_prob == engine_prob. A corrupted engine cell fails the coherence check by design — you cannot ship a market that disagrees with the distribution it came from.

Devigging & uncertainty

Market prices are devigged via Shin. Uncertainty bands come from held-out residuals — not invented. vs_close is labelled UNPROVEN everywhere: the system claims it matches the close, never that it beats it.

Above the engines sit player-prop models and calibration layers. Props synthesize from on-disk gamelogs when an external line feed rate-limits, so the board is never empty; every card carries edge_claimed=false and shows units, never dollars.

6 · In-Game Intelligence

This is the one place with a validated measured advantage — and the genuine frontier for everything beyond matching the close.

The proven part: prior-conditioning calibration

The served in-game number blends the proven pregame prior with realized game state (margin/run-diff, fraction elapsed). Conditioning the static prediction on live state produces a real, measured calibration improvement — statistically decisive on NBA fine-resolution data (Diebold–Mariano p ≈ 1.2×10-12), holding across 3 of 4 sports. This is calibration, labelled as such — not a dollar claim.

Engineering note — carrying the prior across provider-id gaps

The live feed and the pregame snapshot sometimes key the same game under different provider id namespaces, which silently dropped the proven prior (degrading to a weaker base model). A leak-free resolver now bridges this by a unique team match (PRIOR_TEAMS) — exact id first, and on a tie (e.g. a doubleheader) it returns BASE rather than guess. Result: the served in-game number carries the proven prior for more games. Verified on real data; necessary input for the CLV frontier below.

The unproven frontier: in-game CLV

The open question — the real upside — is whether that calibration advantage converts into positive closing-line value against real liquid in-play prices (keyless Kalshi per-game markets, liquidity-gated). The capture loop pairs the model number with the devigged price every tick across live games; an aggregate grader pools per-game CLV with a game-resampling bootstrap and clustered Diebold–Mariano.

The bar for calling it an edge

BEAT requires ≥5 settled games, ≥40 ticks, a settled-outcome arm, a positive pooled-CLV confidence-interval lower bound, and cross-corpus both-direction significance. A pure market-copy candidate is structurally impossible to pass (it yields no corpus). Until that bar is cleared and replicated, vs_close stays UNPROVEN and real money stays DENY. Today: single-corpus, tiny-n — insufficient.

7 · How It Gets Better

"Better" is three distinct things with different levers. Conflating them is how fake edges get born; separating them is how this system stays honest.

Kind of "better"What changesLever / gateStatus
1 · SystemValidation coverage, robustness, the loop itselfAutomatic, continuous (m8 cadence)running
2 · ModelServed calibration actually changesData volume + 5-gate pass + human promoteready / data-gated
3 · EdgeCLV proves positive vs real pricesMany in-season games + replicationunproven

The three improvement engines

  • Living refresh (hourly): newly-settled finals fold into each sport's corpora; the in-game model is re-gated and re-fit, and either swaps in or downgrades its own provenance label. Continuous recalibration on fresh truth.
  • The 5-gate ratchet (daily): the only path that can change a served number — and it never auto-ships; survivors land in proposals.jsonl for a human to promote.
  • CLV as a second corpus: settled closing-line value is leak-free and gate-able, fed to the ratchet as a do-no-harm second corpus — never a ship objective (that is the market-follow trap, structurally blocked).

What "gets better" honestly means

Growing validation coverage and a recalibration engine proven ready that improves calibration when the data earns it — not a fake live-accuracy or edge climb. The served model is static until a gate-passing candidate is promoted. The expected daily outcome is REJECT, and that is the system working: an honest null beats a fabricated edge.

8 · The Validation Discipline & Honesty Rails

The credibility of every claim rests on a gate that rejects almost everything. The discipline is the product.

The gate, in full

  • Leak-free: features are as-of, the outcome is never an input, the close is held out; verified on disk (zero debut-row leaks).
  • Walk-forward / out-of-sample: single-fold lifts are treated as artifacts until they replicate.
  • ≥2 independent corpora, both directions: a signal must survive A→B and B→A, not just one slice.
  • Clustered Diebold–Mariano by game: significance that respects within-game correlation.
  • FWER budget + planted-null tripwire: the bar tightens as more candidates are tested; a null that "passes" freezes its whole family — proof the gate has teeth.
  • Degenerate-base guard & collinearity check: no winning by a broken baseline or by restating the base.

Numbers that are permanently retracted

Certain early figures were measurement artifacts (market-follow grading, a Q4 leak, an L5-proxy ceiling) and are never presented as current results. They appear only inside an explicit retraction context. Honesty is enforced, not aspirational: the served product carries no dollar fields, and a single boolean flips the whole status to "not honest" if a dollar/edge/stale-green/real-money leak ever appears.

The binding invariants (held even unattended, for days)

Never claim a dollar edge or print a retracted number.
Never auto-ship a model change or flip a feature flag on.
Never enable real money — it stays default-DENY.
Never push private data/ledgers to the public origin.
Always stale-never-green: dead reads red.
Always record honest rejects — they are the deliverable.

9 · The Intelligence Layer & Memory

Beneath the predictions sits a navigable knowledge graph — the system's long-term understanding of the sport — plus an auto-memory that lets the agentic builder carry lessons across sessions.

The Obsidian Brain

  • 872 notes, 100% reachable, one connected component, person-free.
  • Player dossiers, scheme atlases, archetype hubs, comparables, game plans, leaderboards, lineup chemistry.
  • An 80-artifact intelligence manifest + a reject ledger (the signal graveyard).
  • Three self-policing graph gates keep it coherent on every rebuild.

Auto-Memory (cross-session)

  • One fact per file: user profile, feedback, project state, references.
  • Lets the agentic pipeline remember decisions, landmines, and "do-not-claim" rules between runs.
  • Verified against the live code before reuse — memory informs, it never overrides what the repo actually says.

Scouting vs serving — the key distinction

Most ingested signals REJECT at the gate. Rejected signals are not discarded — they become validated scouting: recorded, searchable intelligence about what does and does not move a sport. They are never force-fed into the served prediction, because force-feeding a rejected signal is exactly the overfitting / market-follow failure mode the whole discipline exists to prevent. The intelligence layer is therefore an honest map of the sport's predictability frontier, not a pile of unused features.

The meta-finding (the plateau)

Tested at the finest available on-disk grids across all four sports — coarse state → at-bat / per-pitch / Statcast → CV aggregates → playstyle correlations — deeper data rejects for held-out win-probability calibration beyond the (margin/time) base plus the pregame prior. Recording that plateau, under gates proven to both fail noise and pass real signal, is a genuine scientific deliverable. One confirmed survivor (a soccer corners signal) cleared the hardest six-control gate — tiny in magnitude, real in fact, and still labelled calibration-only.

11 · Where It Can Go

This is the start, not the finish. The foundation is built and honest; the frontier is wide. Below: the founder's thesis, with proven foundation and aspirational frontier clearly separated.

The thesis

An originated, end-to-end sports-detail funnel — CV tracking through one coherent prediction through a self-validating loop — is a genuinely new kind of system. It is hard precisely because it has not been done this way before. The asset compounds: every day of in-season data, every deeper data tier, and every improvement to the CV identity layer feeds the same brutal gate, and the survivors are real because the gate is real.

The honest ceiling — and why it is a good one

Pregame: match the close (essentially reached — a real, defensible result). In-game: a small measured conditioning edge whose conversion to CLV is the open prize; if it replicates in liquid markets, that is rare and valuable precisely because almost everything else rejects. As intelligence and product: a high and largely realized ceiling — the most-complete, honestly-calibrated, self-validating multi-sport forecaster, with a CV data tier as its moat. The path to "edges on its own" is in-season volume + deeper data + the CV layer, all poured into the same uncompromising gate. Capital accelerates the data and the tracking; it does not change the discipline — and the discipline is what makes it true.

What to do next, concretely

  1. Leave it running through in-season volume — the CLV verdict needs games, not code.
  2. Acquire deeper data tiers and feed them to the existing gate (expect mostly rejects).
  3. Invest in the CV identity layer — the one data source nobody can buy.
  4. Promote only gate-survivors; keep real money DENY until CLV is replicated-positive.
  5. Generalize the kernel/adapter platform to new sports.
